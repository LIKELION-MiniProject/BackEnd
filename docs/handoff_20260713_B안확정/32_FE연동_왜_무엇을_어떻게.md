# 32. 프론트엔드 연동 — 왜 · 무엇을 · 어떻게 (내용 정리 3)

> 대상: FE(인서, React 19 + Vite 8). BE(Spring recommend + auth) 준비 완료 → 이제 **목업을 실 API로 교체**하는 단계.

## 1) 왜 연동하나 (지금이 시점)
- BE가 계약 v2.1대로 완성됨: `POST/GET /api/v1/profiles/{id}/recommendations`(캐시 서빙), 인증(signup/login/me), CORS(5173·5174).
- FE는 화면(기본 보기 + 비교, 정상/기본추천)이 이미 완성 → **남은 건 데이터 소스를 목업 → 실서버로 바꾸는 것뿐**.
- 7/15 게이트("화면에서 로그인→진단→AI추천 1회 통과")를 통과하려면 이 연동이 핵심 경로.

## 2) 무엇을 연동하나 (엔드포인트 계약)

| 화면 | 호출 | 요청 | 응답 |
|---|---|---|---|
| 회원가입 | `POST /api/v1/auth/signup` | `{email, password(≥8), nickname}` | `{success,data:{id,email,nickname},message}` |
| 로그인 | `POST /api/v1/auth/login` | `{email, password}` | `data:{accessToken, tokenType:"Bearer", userId, nickname}` |
| 내정보/온보딩 분기 | `GET /api/v1/auth/me` | (Bearer) | `data:{id,email,nickname,profileId}` — **profileId null이면 온보딩** |
| 프로필 | `POST /profiles`, `GET/PATCH /profiles/{id}` | 학과·학번 등 | 소유자만 |
| 수강이력 | `GET/POST/PUT/DELETE /profiles/{id}/courses` | | 복붙은 AI 파싱 |
| 진단/GPA/대시보드 | `GET /profiles/{id}/diagnosis` · `/gpa-trend` · `/dashboard` | (Bearer) | 규칙/집계 |
| **AI 추천** | `GET /profiles/{id}/recommendations` | (Bearer) | **계약 v2.1**(아래) |

AI 추천 `data` = `{ recommendations[], directions[], defaultDirectionId, source, generatedAt }`
- `directions[]`: `{ directionId, name, description, caution, thin, recommendations[] }`
- 항목: `{ courseCode, courseName, credit, category, reasons[3] }` (reasons 순서 고정 [성향·특성·요건])

## 3) 어떻게 연동하나 (단계)

### 0단계 — 토큰 저장/주입
- 로그인 응답의 `accessToken`을 메모리/`localStorage`(팀 정책 따라)에 저장.
- 모든 인증 요청에 `Authorization: Bearer <token>` 헤더. 401 시 로그인으로.

### 1단계 — API 래퍼
```js
// src/api/client.js
const BASE = "/api/v1";
export async function api(path, { method="GET", body, token } = {}) {
  const res = await fetch(BASE + path, {
    method,
    headers: { "Content-Type": "application/json", ...(token && { Authorization: `Bearer ${token}` }) },
    ...(body && { body: JSON.stringify(body) }),
  });
  const json = await res.json();           // { success, data, message }
  if (!res.ok || !json.success) throw new Error(json.message || `HTTP ${res.status}`);
  return json.data;
}
```

### 2단계 — Vite 프록시(개발 CORS 회피, 선택)
```js
// vite.config.js
server: { port: 5173, proxy: { "/api": { target: "http://localhost:8080", changeOrigin: true } } }
```
- 프록시를 쓰면 same-origin이라 CORS 신경 덜 씀. 안 쓰면 BE CorsConfig(5173·5174)가 이미 허용.

### 3단계 — AI 분석 페이지: 목업 → 실 API 교체
- 현재 `AiAnalysisPage.jsx`의 내장 `DIRS`(임시 데이터) 제거.
- `GET /profiles/{id}/recommendations` 결과의 `data`를 그대로 주입:
```js
const data = await api(`/profiles/${profileId}/recommendations`, { token });
const [dir, setDir] = useState(data.defaultDirectionId);
const active = data.directions.find(d => d.directionId === dir);
// active.recommendations → 카드 5장, active.caution → 빨간 글씨(있을 때), active.thin → thin 박스
// data.source === "fallback" → "기본 추천" 배지
```
- **탭 전환·비교는 그대로 클라이언트 처리**(서버 재호출 없음).
- ⚠️ 내장 임시 과목명(대학영어 등) 제거 필수 → 실데이터로 대체(우리 목업 `docs/.../mocks/reco.*.json` 또는 실 API).

### 4단계 — 상태 처리(29 문서 디자인 연계)
- 로딩: 탭+카드 스켈레톤. 에러: 재시도 카드. 빈: 안내.
- `source==fallback` → 앰버 "기본 추천" 배지. `caution!=null` → 빨간 글씨. `thin` → thin 박스.

### 5단계 — 스탯 카드(상단 3종) 출처 확인
- 성적분석%·졸업요건충족률%·선수과목 확인은 **추천 응답 밖**. 진단/GPA/대시보드 API에서 바인딩하거나 데모 하드코딩.
- **인서 확인 후 원석 보고**(계약 v2.1 §9). 추천 API에 넣지 않는다.

## 4) 연동 순서 권장(의존성)
로그인/회원가입 → me(온보딩 분기) → 프로필 → 수강이력 → 진단/GPA/대시보드 → **AI 추천**. (7/15 게이트 = 이 전체 1회 관통)

## 5) BE가 이미 보장하는 것(FE가 안 해도 됨)
- CORS(5173·5174 + Authorization). 소유권 검증(타인 프로필 403). 응답 래퍼 `{success,data,message}` 일관.
- 추천 결정성(같은 프로필 = 같은 결과, 캐시 서빙). AI 실패 시 자동 폴백 + `source=fallback`.
