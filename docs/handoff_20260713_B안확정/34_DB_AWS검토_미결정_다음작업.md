# 34. DB(AWS) 검토 · 미결정 · 다음 작업 (코드/작업 정리 2)

## A. "다른 유저가 쓰게 AWS DB로?" — 검토 결과

### 현재 상태
- DB = **H2 인메모리**(`jdbc:h2:mem:passportdb`). 앱이 켜져 있는 동안만 데이터 존재, **서버 재시작 시 전부 초기화**.
- 회원가입·로그인·프로필·수강이력·인증은 정상 저장되지만 **휘발성**.

### "다른 유저가 사용"의 두 해석
1. **발표 데모에서 여러 명이 각자 가입해 써본다** → 서버 1대 띄워두면 H2로도 재시작 전까지 동작. **AWS 불필요**.
2. **상시 배포된 서비스로 여러 사용자가 지속 사용/데이터 유지** → 영속 DB + 배포(서버 호스팅) 필요.

### 선택지 비교

| 방식 | 영속성 | 다중접속 | 작업량 | 비용 | 마감(7/17) 적합성 |
|---|---|---|---|---|---|
| **H2 인메모리(현재)** | ❌ 재시작 소실 | 앱 1대 내 | 0 | 무료 | 발표엔 OK(시딩 전제) |
| **H2 파일 모드** | ✅ 파일로 유지 | 앱 1대 내 | **설정 1줄** | 무료 | ★ 권장(영속성 필요 시) |
| 로컬 MySQL/PostgreSQL | ✅ | 로컬 다중 | 중 | 무료 | 여유 있으면 |
| **AWS RDS + EC2 배포** | ✅ | 진짜 다중/원격 | 큼(보안·배포·자격증명) | 과금 | 마감 내 위험, 발표 후 확장 과제 |

### 권장 (단계적)
1. **마감 전**: 데이터가 재시작에도 남아야 하면 **H2 파일 모드로 전환**(아래 설정). 아니면 인메모리 유지 + 데모 시딩.
2. **발표 후/심사에 "배포 서비스" 요건이 있으면**: AWS RDS(MySQL/PostgreSQL) + EC2/앱러너 배포를 **별도 시간 확보 후** 진행. 자격증명은 환경변수, 보안그룹·SSL 필수.
3. ⚠️ AWS를 지금 급히 붙이면 마감 리스크(배포·CORS·보안·비용)가 커서 **비권장**. 완성도 우선 원칙(원칙 5)과도 배치.

### H2 파일 모드 전환 (영속성만 원하면, 코드 1줄)
`application.yml`:
```yaml
  datasource:
    url: jdbc:h2:file:./data/passportdb;AUTO_SERVER=TRUE   # mem → file
```
- `./data/passportdb.mv.db` 파일로 저장돼 재시작해도 유지. `.gitignore`에 `data/*.db` 추가 권장.
- 실제 RDS 전환 시엔 MySQL/PostgreSQL 드라이버 의존성 + url/username/password 환경변수만 교체(JPA라 엔티티 변경 없음).

> 결론: **지금은 AWS 불필요.** 영속성이 필요하면 H2 파일 모드로 충분. AWS RDS는 "배포된 다중 사용자 서비스"가 목표일 때 발표 후 확장으로.
