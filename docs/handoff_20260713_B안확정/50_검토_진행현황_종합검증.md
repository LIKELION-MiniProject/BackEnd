## 1. 한 줄 요약
백엔드는 **AI 추천(B안 5방향) + 졸업요건 유저저장 + 대시보드 확장 + 인증 5분야 진단연결 + H2 파일영속 + CORS**까지 구현·호스트 검증 완료. 프론트는 화면 완성, 실 API 연동만 남음. **최대 리스크는 "모든 작업이 아직 미커밋(GitHub 미반영)"**. 다음 우선순위: 커밋/푸쉬 → FE 연동 → Gemini 모델 교체(3.1-flash-lite).

## 3. 이번 세션에서 실제로 검증한 것 (증거 포함)
1. **연결 레포에 전 작업 반영 확인** — recommendation·requirement·dashboard·course·cors·passport-ai 파일 실재(코드 read로 확인).
2. **AI 추천 규칙 로직** — 실 `courses.json`로 재현: 데모 학생 → FAST_GRAD(5)·GRADE_SAFE(thin,1)·EXAM_SOLO(5,caution)·TEAM_ACTIVE(thin,2), MAJOR_DEEP 제외. thin·caution·category 정상.
3. **Spring 컴파일·기동** — `gradlew bootRun`이 에러 없이 `Started PassportApplication`, Tomcat 8080. (STEP E 자바 변경이 컴파일 통과했다는 증거)
4. **DB 파일 영속** — `jdbc:h2:file` 전환, data.sql을 MERGE로 바꿔 재기동 시 unique 충돌 없이 기동.
5. **요건 PUT 저장** — PowerShell UTF-8 바이트로 전송 시 `success:true, source:user`. (500은 PS 인코딩 문제였고 해결)
6. **STEP E 진단 연결(핵심)** — `GET /diagnosis` 응답에 `graduationCertification`(5분야 + fulfilled) 생성. `foreignLangCert="대상"`(미완료) → `fulfilled:false`, 이후 `"완료"`로 바꿔 재저장 → **`fulfilled:true`로 정확히 토글됨**. 규칙·저장 정상 확정.
7. **deptCode** — `BIGDATA_AI`로 진단 resolve 정상(하드코딩 요건 매칭됨).
8. **푸쉬 안전** — `.env`·`data/`·`*.mv.db` gitignore 무시, 추적/신규 파일에 API 키 노출 없음.

## 4. ⚠️ 검토 시 반드시 확인할 3가지 (정직한 갭)
1. **미커밋 상태 = 최대 리스크.** 지금까지 전부 원석 PC 로컬에만 있음(초기 커밋 1개뿐). GitHub push 전엔 유실 위험. → 51·52 문서에 커밋 명령.
2. **"라이브 AI vs 사전 캐시" 구조.** Spring 추천은 요청 시 AI를 라이브 호출하지 않고 **사전 생성 캐시(cache/{studentId}.json)를 서빙**하거나, 캐시 없으면 **진단 기반 규칙 폴백**(구분 단위)한다. "내 실시간 입력 → AI가 구체 과목 추천"의 완전 자동 파이프라인(Spring↔passport-ai 브릿지)은 **미구현(의도된 B안 설계)**. → 상세 51 문서 §5.
3. **STEP E 판정 방식(원석 사인 필요).** 현재 "기존 인증(LANGUAGE/VOLUNTEER/THESIS) 판정 + 5분야 판정을 **둘 다 AND**"(보수적). "5분야 입력 시 5분야만으로"로 바꿀지 팀 결정 필요(1줄 수정). → 51 문서 §4.

## 5. 결과 일관성(비결정성) — 검토 결론
- Spring 추천은 **정적 캐시 서빙 → 같은 프로필이면 항상 동일**(결정적).
- 방향 분류·후보는 100% 규칙 → **같은 방향이면 후보 집합 동일**, AI는 그 안에서 5개 선택·이유 문구만 `temperature=0.3`으로 약간 변동. 원석 요구("방향 같으면 대체로 동일, 과목은 좀 달라도 OK")와 일치.
- 완전 고정 원하면 temperature 0.1/0으로(선택).
