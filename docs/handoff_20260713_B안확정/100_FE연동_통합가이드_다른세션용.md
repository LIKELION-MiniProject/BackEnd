## 5. 🔴 오늘(7/16) 바뀐 계약 2건

### ① `credit` 정수 → **소수** (0.5학점 지원)

| 필드 | 이전 | 지금 |
|---|---|---|
| `courses[].credit` | `3` | **`3.0`** |
| `totalCredit.earned` / `shortfall` | `39` / `91` | **`39.0`** / **`91.0`** |
| `categories[].current` (대시보드) | `39` | **`39.0`** |
| `semesters[].earnedCredit` | `22` | **`22.0`** |
| `requestedCredits`/`earnedCredits` | `22` | **`22.0`** |

**대부분 아무것도 안 해도 됩니다.** JS에서 `3.0`은 그냥 `3`이고 `` `${3}` ``은 `"3"`입니다.

```js
// ❌ "3.0학점"으로 보임
`${c.credit.toFixed(1)}학점`
// ✅ 그냥 쓰면 됨
`${c.credit}학점`      // 3 → "3",  0.5 → "0.5"
```

- **`required`는 여전히 정수**(요건 기준값 130·21·39는 소수 없음). 소수는 "이수 학점" 쪽에만 생긴다.
- **입력 허용값: 0 이상 30 이하 0.5 단위.** `3.333` → `400 COMMON-001`
- **학점 드롭다운에 0.5를 넣어야** `인성과미래설계Ⅰ`(0.5학점)을 입력할 수 있다:
  ```js
  const CREDIT_OPTIONS = [0, 0.5, 1, 1.5, 2, 2.5, 3, 4, 5, 6];
  ```

### ② `exam`·`coreLiberal` → **`"미입력"`**

| key | 이전 | 지금 |
|---|---|---|
| `exam` (졸업시험/논문) | `status:"완료"` 🔴 버그 | `current:null, required:null, **status:"미입력"**` |
| `coreLiberal` (핵심 교양) | `current:0, required:5, "진행중"` | `current:null, required:null, **status:"미입력"**` |

**FE 처리**: `status==="미입력"` 또는 `required==null` 이면 **막대·퍼센트를 그리지 말 것.** 상태 텍스트만.

```js
const drawBar = (c) => c.required != null && c.status !== '미입력';
```

- `exam`이 "완료"였던 건 계산이 아니라 **버그**였다. 빅데이터AI 전공은 `thesisCertRequired=false`라 "졸업시험 요건 없음"으로 resolve됐고, 그게 "완료"로 잘못 매핑돼 있었다.
- `coreLiberal`의 `0/5`는 "5영역 중 0개 이수"가 아니라 **"대상 영역 수"**였다. 과목↔영역 매핑 데이터가 없어 이수 영역을 계산할 수 없다.
- `requiredCourse`는 **그대로**(`required:null`, `unit:"건"`).

#### 🔴 GPA 그래프 라벨 — 학년 계산을 쓰면 안 된다

**현재 FE가 `3-1`(다닌 적 없는 학기)을 표시하고 있다.** 원인은 하드코딩이 아니라 **계산식**이다:

```js
// ❌ 지금 (군휴학 2년이 학년에 그대로 더해짐)
const label = `${s.year - admissionYear + 1}-${s.semester}`;
//  2024 - 2024 + 1 = 1  →  "1-1"  (우연히 맞음)
//  2026 - 2024 + 1 = 3  →  "3-1"  (실제는 2학년!)

// ✅ 서버가 준 값을 그대로
const label = `${s.year}-${s.semester}`;   // "2024-1", "2026-1"
```

**학년 표기는 서버가 지원할 수 없다.** `profile.grade`는 **현재** 학년(2)뿐이고, 과거 각 학기가 몇 학년이었는지는 어디에도 없다. 원석은 `1학년1학기 → 2학년1학기`로 **1학년 2학기를 건너뛰어서** 거꾸로 세도 틀린다. **`연도-학기`가 유일하게 정확하다.**

- `predicted:true`는 **예측치**(규칙 기반 외삽, AI 아님) → **점선·회색**으로 구분. `earnedCredit:0.0`이니 학점 표시 생략.
- `gpa:null`이면 그 학기에 GPA 대상 과목이 없다는 뜻 → 점 찍지 말 것.
- **`categoryGpa`의 `기초`·`기타`가 `null`인 것은 정상** (전공기초를 전공필수로 입력하기로 합의, 자유선택 미이수) → **`-`로 표시.** `null.toFixed()`는 터진다.

## 7. 🔴 오독하기 쉬운 응답 5건

### ① `certifications[].fulfilled` — 체크 아이콘으로 쓰면 안 된다

```json
{ "type": "THESIS", "required": false, "fulfilled": true, "status": "NOT_SUBMITTED" }
```

모순처럼 보이지만 정상이다. **`fulfilled`은 "이수했다"가 아니라 "졸업을 막지 않는다"는 뜻이다.** 필수가 아닌 인증은 제출 안 해도 졸업에 지장이 없으므로 `true`다. (`eligibleForGraduation` 계산에 쓰인다.)

| 표시할 것 | 쓸 필드 |
|---|---|
| 체크/미체크 아이콘 | **`status`** (`PASS`·`FAIL`·`NOT_SUBMITTED`) |
| 이 인증이 나에게 필수인가 | `required` |
| ❌ 절대 체크 표시로 쓰지 말 것 | ~~`fulfilled`~~ |

`required:false` 항목에 초록 체크를 그리면 **"졸업논문 완료"로 오해**된다.

### ② 졸업 인증이 **두 종류**다 (이름이 겹쳐 헷갈림)

| 구분 | 엔드포인트 | 값 |
|---|---|---|
| **졸업 인증 체크** | `GET`/`PUT` `/profiles/{id}/certifications` | `LANGUAGE`·`VOLUNTEER`·`THESIS` × **`PASS`·`FAIL`·`NOT_SUBMITTED`** |
| **요건 입력 5분야** | `PUT /profiles/{id}/requirements`의 `certification` | `foreignLangCert`·`infoProcessing`·`cpr`·`socialService`·`foreignLangExtra` × **`TARGET`·`NOT_TARGET`·`DONE`** |

> **"요건 현황에 졸업 인증제 데이터가 없다"** — API는 처음부터 있었고 **아무도 입력을 안 해서 값이 비어 있던 것**이다. 원석이 실제 상태를 입력했다.

`PUT /profiles/1/certifications` 요청 본문:
```json
{ "items": [
  { "type": "LANGUAGE",  "status": "NOT_SUBMITTED" },
  { "type": "VOLUNTEER", "status": "NOT_SUBMITTED" },
  { "type": "THESIS",    "status": "NOT_SUBMITTED" }
] }
```

### ③ `category`에 `MAJOR_BASIC`(전공기초)이 **있지만 보내면 안 된다**

허용값: `MAJOR_BASIC` `MAJOR_REQUIRED` `MAJOR_ELECTIVE` `GE_REQUIRED` `GE_ELECTIVE` `GENERAL_ELECTIVE`

🔴 **`MAJOR_BASIC`을 보내면 400이 안 나고 조용히 저장된 뒤 진단이 어긋난다.** 요건이 `majorBasic:0`이기 때문이다. **팀 합의는 전공기초 = `MAJOR_REQUIRED`로 입력**이고 서버의 현재 데이터가 전부 그렇게 들어가 있다. (`categoryGpa`의 `기초`가 `null`인 것도 이 합의의 결과다.)

### ④ `PATCH /profiles/{id}` · `PUT /courses/{cid}` — **전체 필드 전송 필수**

일부만 보내면 **나머지가 `null`로 덮어써진다.** `ProfileUpdateRequest`는 11필드 전체 교체다.

### ⑤ `enrollmentStatus`는 3개뿐

`"재학생"` · `"휴학생"` · `"졸업 예정"`. **"군제대복학"은 없다.** 원석은 `"재학생"`이다.

## 9. 로그인 오류 문구 — BE는 정상, FE 텍스트 문제

로그인 실패 시 서버는 **이메일이 없든 비밀번호가 틀리든 똑같이** 내려준다:

```json
HTTP 401
{ "code": "AUTH-002", "message": "이메일 또는 비밀번호가 올바르지 않습니다." }
```

**의도된 동작이다.** 둘을 구분하면 "이 이메일은 가입돼 있다"는 정보가 새어나간다(계정 열거 공격).

→ 로그인 화면의 **"이미 등록된 이메일"은 서버가 보낸 문구가 아니다.** FE 하드코딩이니 제거할 것.

| 상황 | 응답 | 화면 |
|---|---|---|
| 로그인 실패 | `401 AUTH-002` | 서버 `message` 그대로 |
| **회원가입** 이메일 중복 | `409 AUTH-001 "이미 사용 중인 이메일입니다."` | 서버 `message` 그대로 |

회원가입에서만 중복을 알려주는 게 맞다.

## 10. 요건 입력 카드 — **살려야 한다**

과거에 "백엔드에 저장 API가 없으니 카드를 숨기자"는 결정이 있었는데 **그 전제가 사실이 아니었다. API는 실재한다.**

```
GET  /api/v1/profiles/{id}/requirements    저장된 요건 조회
PUT  /api/v1/profiles/{id}/requirements    요건 저장
```

저장한 요건은 **이미 진단·대시보드에 자동 반영**된다(유저 저장값 우선, 없으면 학과 하드코딩 폴백).

`PUT` 본문 (신영 요건 입력 화면 5섹션):
```json
{
  "credits": {
    "total": 130, "majorRequired": 21, "majorElective": 39, "majorBasic": 0,
    "liberalRequired": 14, "liberalElective": 21, "majorTotal": 60, "liberalTotal": 35,
    "teaching": 0, "generalElective": 35, "external": 0, "doubleMajor": 0,
    "minor": 0, "linkedMajor": 0, "convergenceMajor": 0
  },
  "requiredCourseType": "...",
  "coreLiberal": [
    { "areaNo": 1, "areaName": "언어와 문학", "courseCount": 1, "credit": 3, "target": true }
  ],
  "certification": {
    "foreignLangCert": "TARGET", "infoProcessing": "NOT_TARGET",
    "cpr": "TARGET", "socialService": "TARGET", "foreignLangExtra": "NOT_TARGET"
  },
  "graduationExam": "NONE",
  "draft": false
}
```

- `credits`는 **15필드 전부 정수, 전체 전송**
- `graduationExam`: `NONE` · `THESIS` · `EXAM` · `EITHER`
- `coreLiberal[].target`은 "이 영역이 나에게 해당하는가"이지 **이수 여부가 아니다**
- **`graduationExam`을 `THESIS`/`EITHER`로 저장하면** 대시보드 `exam`이 `"미입력"` 대신 인증 데이터 기반 판정을 시작한다 (§5-② 해소 경로)

## 11. 400 유발 요인 정리

| 항목 | 규칙 |
|---|---|
| `grade` | `A+` `A` `B+` `B` `C+` `C` `D+` `D` `F` `P` `NP` 만. 화면 **`A0`** → 서버 **`"A"`**. `A5` 같은 표기 없음 |
| `credit` | **0 이상 30 이하 0.5 단위.** `3.333` → `400 COMMON-001` |
| `category` | 6종. **`MAJOR_BASIC`은 보내지 말 것**(§7-③) |
| `PATCH /profiles` | 11필드 **전체** |
| `PUT /courses/{cid}` | **전체** 필드 |
| `PUT /requirements` | `credits` 15필드 **전부 정수, 전체** |
| 비밀번호 | 회원가입 시 **8자 이상** |

### 주요 에러 코드

| code | HTTP | 의미 |
|---|---|---|
| `COMMON-001` | 400 | 입력값 오류 (`message`에 상세) |
| `AUTH-001` | 409 | 이메일 중복 (회원가입) |
| `AUTH-002` | 401 | 로그인 실패 |
| `AUTH-003` | 401 | 인증 필요 (토큰 없음/만료) |
| `PROFILE-001` | 404 | 프로필 없음 |
| `PROFILE-003` | 403 | **타인 프로필 접근** (정상 동작) |
| `COURSE-001` | 404 | 수강 이력 없음 |

## 12. 코드 예시 — 수강 CRUD (최우선 작업)

```js
const API = import.meta.env.VITE_API_BASE_URL;   // "/api/v1"
const token = localStorage.getItem("accessToken");
const H = { "Content-Type": "application/json", Authorization: `Bearer ${token}` };

// 1) 진입 시 로드
const loadCourses = async (profileId) => {
  const r = await fetch(`${API}/profiles/${profileId}/courses`, { headers: H });
  const j = await r.json();
  return j.data;                     // 16과목 전부
};

// 2) 추가  ← 최우선
const addCourse = async (profileId, form) => {
  const r = await fetch(`${API}/profiles/${profileId}/courses`, {
    method: "POST", headers: H,
    body: JSON.stringify({
      name: form.name,
      credit: form.credit,           // 3 또는 0.5 (0.5 단위)
      category: form.category,       // "MAJOR_REQUIRED" 등 (MAJOR_BASIC 금지)
      grade: form.grade,             // "A" (A0 아님!)
      year: form.year,
      semester: form.semester,
      retake: form.retake ?? false,
    }),
  });
  if (!r.ok) { const e = await r.json(); throw new Error(e.message); }
  return (await r.json()).data;
};

// 3) 수정 — ⚠️ 전체 필드
const updateCourse = async (profileId, courseId, form) => {
  const r = await fetch(`${API}/profiles/${profileId}/courses/${courseId}`, {
    method: "PUT", headers: H,
    body: JSON.stringify({
      name: form.name, credit: form.credit, category: form.category,
      grade: form.grade, year: form.year, semester: form.semester,
      retake: form.retake ?? false,      // 하나라도 빠지면 null로 덮어써짐
    }),
  });
  if (!r.ok) throw new Error((await r.json()).message);
  return (await r.json()).data;
};

// 4) 삭제
const deleteCourse = (profileId, courseId) =>
  fetch(`${API}/profiles/${profileId}/courses/${courseId}`, { method: "DELETE", headers: H });

// 5) 저장 후 반드시 대시보드 재조회 (숫자 갱신)
const refreshDashboard = async (profileId) => {
  const r = await fetch(`${API}/profiles/${profileId}/dashboard`, { headers: H });
  return (await r.json()).data;
};

// 6) "AI 분석" 버튼 — POST + 로딩
const runAiAnalysis = async (profileId, setLoading) => {
  setLoading(true);
  try {
    const r = await fetch(`${API}/profiles/${profileId}/recommendations`, {
      method: "POST", headers: H, body: "{}",
    });
    return (await r.json()).data;     // 변동 없으면 즉시, 있으면 수 초
  } finally { setLoading(false); }
};
```
