# 프론트-백엔드 연동, 쉽게 이해하기 (비전공자용)

> 목적: "연동이 뭔지, 어떻게 이뤄지는지" 전혀 몰라도 이해되도록 쉬운 말로 정리. 그리고 실제로 무엇을·왜·어떻게 해야 하는지까지.

---

## 1. 연동이 뭐예요? (식당 비유)

우리 서비스는 크게 두 덩어리로 되어 있어요.

- **프론트(FE)** = 손님이 보는 **홀과 메뉴판**. 화면·버튼·글자 등 눈에 보이는 전부.
- **백엔드(BE)** = 안 보이는 **주방**. 데이터를 저장하고, 계산하고, AI 추천을 만드는 진짜 일꾼.

손님이 화면에서 버튼을 누르면:
1. 프론트가 주방(백엔드)에 **"주문서"를 보냅니다** (예: "이 학생 추천 과목 만들어줘").
2. 백엔드가 **요리를 합니다** (DB 조회 → 계산 → AI 분석).
3. 백엔드가 **완성된 접시(답)를 돌려줍니다**.
4. 프론트가 그 답을 받아 **화면에 예쁘게 올립니다**.

**"연동(連動)"** = 지금 화면에 놓인 **가짜 모형 음식(목업 데이터)**을 치우고, **진짜 주방과 연결해서 실제 요리가 나오게** 만드는 작업이에요.

---

## 2. 지금 우리 상황

- **주방(백엔드)은 완성**됐어요. 회원가입·로그인·성적 저장·졸업 진단·AI 추천까지 다 되고, 서버를 켜면(`gradlew bootRun`) 주문을 받을 준비 완료.
- **홀(프론트)의 화면도 거의 완성**됐어요. 단, 아직 **가짜 모형 음식(목업)**이 올라가 있어요.
- 남은 일 = **홀과 주방을 연결**(연동)해서 진짜 데이터가 흐르게 하는 것. 이 코드는 **인서님이** 씁니다.

---

## 3. 주문서 양식 = "API" (왜 정해두나)

주방에 아무렇게나 말하면 못 알아들어요. 그래서 **주문서 양식(API)**을 미리 정해뒀습니다. 예:
- "로그인 주문" → 이메일·비밀번호를 담아 보냄 → 주방이 **출입증(토큰)**을 줌.
- "추천 주문" → 출입증을 보여주며 요청 → 주방이 **방향 5개 + 과목 카드**를 줌.

**출입증(토큰)이 중요해요**: 로그인하면 백엔드가 출입증을 하나 줍니다. 이후 모든 주문에는 **이 출입증을 같이 내밀어야** 주방이 "아, 이 손님 맞네" 하고 처리해줘요. (출입증 없으면 "누구세요?"하고 거절 = 로그인 화면으로.)

---

## 4. 무엇을·왜·어떻게 (연동 순서, 쉬운 설명)

아래는 인서님이 화면 하나씩 진짜 주방에 연결하는 순서예요. **위에서부터** 해야 뒤에 것이 돌아갑니다(로그인 없이 추천 못 받으니까요).

### ① 출입증 창구 만들기 (API 클라이언트)
- **무엇**: 모든 주문에 출입증을 자동으로 끼워 보내는 "공용 창구" 코드 하나.
- **왜**: 화면마다 출입증 넣는 코드를 반복하지 않으려고. 한 곳에서 처리.
- **어떻게**: `client.js`라는 파일 하나 만들어, 여기로만 주문을 보내게. (상세 코드는 개발자용 문서 `54` 참고)

### ② 로그인 → "이 손님 처음이야?" 판단
- **무엇**: 로그인하면 출입증 저장. 그리고 "이 사람 프로필 있어?"를 물어봄.
- **왜**: 프로필(학과·학번)이 없는 신규 손님은 **먼저 프로필부터** 만들어야 나머지가 돌아가요.
- **어떻게**: 로그인 응답의 출입증 저장 → "내 정보(me)" 주문 → 거기 `프로필ID`가 비어 있으면 **프로필 만들기 화면으로**, 있으면 **대시보드로**.

### ③ 프로필 만들기 화면 (지금 없음 — 새로 필요)
- **무엇**: 신규 손님에게 학과·학번·입학연도·이름을 받는 첫 화면.
- **왜**: 이게 있어야 그 사람 전용 "장부(내 데이터)"가 생겨요.
- **어떻게**: 간단한 입력 폼 → 저장하면 프로필ID가 생기고 다음 단계로.

### ④ 성적·졸업요건 입력 → 저장 (내 장부 만들기)
- **무엇**: 들은 과목·성적, 졸업요건을 입력해 백엔드에 저장.
- **왜**: 이게 있어야 백엔드가 "너 뭐 부족해"를 계산하고, AI가 추천해줄 재료가 생겨요.
- **어떻게**: 화면은 이미 있으니 **가짜 데이터 대신 진짜 주방으로** 보내게 연결만. (성적 저장하면 실제로 내 장부에 쌓입니다 — 백엔드에서 확인 완료.)

### ⑤ 진단·대시보드 보여주기 (+ 딱 한 줄 수정)
- **무엇**: "졸업까지 얼마 남았나" 요약을 화면에.
- **왜**: 내가 입력한 성적을 근거로 계산한 결과를 보여주려고.
- **어떻게**: 진단·대시보드 주문 연결. **딱 하나**, 학기 평점 표시하는 부분의 이름을 `gpa` → `semesterGpa`로 바꾸면 끝(백엔드가 그 이름으로 줘요).

### ⑥ ⭐ AI 분석 (여기가 제일 중요 — 동작이 특별해요)
- **무엇**: "AI 분석하기" 버튼을 누르면 방향 5개 + 추천 과목이 나옴.
- **왜**: 이게 우리 서비스의 핵심 기능.
- **어떻게 / 꼭 알 점**:
  - 버튼(POST 주문)을 누르면, **성적·요건·자격증이 바뀌었을 때만 AI가 새로 분석**하고(약 **5~6초 걸림**), 안 바뀌었으면 **바로 이전 결과**를 줍니다.
  - 그래서 **"분석 중이에요…" 로딩 화면이 꼭 필요**해요(6초 동안 빈 화면이면 손님이 멈춘 줄 알아요).
  - 방향 탭을 눌러 이리저리 보는 건 **이미 받은 결과 안에서** 바뀌는 거라, 그때마다 주방을 다시 부르지 않아요(빠릅니다).
  - 카드에는 과목명·학점·구분과 **추천 이유 3줄**(나에게 맞음/과목 특성/졸업·전공 도움)이 있고, 특정 방향엔 **빨간 주의 문구**가 붙어요(백엔드가 줌).

### ⑦ 로딩·에러·빈 화면 처리 + 전체 한 번 통과
- **무엇**: 기다리는 중/문제 생김/텅 빔 상태를 각각 표시.
- **왜**: 실제로 쓰다 보면 늦거나 실패할 때가 있어서.
- **어떻게**: 신영님 디자인(문서 `29b`) 붙이고, **로그인→프로필→성적→대시보드→AI 분석**을 처음부터 끝까지 **한 번 성공**시키기(이게 7/15 점검 통과 조건).

---

## 5. 원석님(백엔드/PM)이 할 일 vs 인서님(프론트)이 할 일

| 일 | 담당 |
|---|---|
| 백엔드 서버 켜두기(`bootRun`), API가 올바른 답 주는지 보장 | 원석 |
| 문제 생기면 백엔드 고치기, 궁금한 응답 형식 알려주기 | 원석 |
| **화면 ↔ 백엔드 연결 코드 작성**(위 ①~⑦) | 인서 |
| 디자인(로딩·에러·경고) 제공 | 신영 |

## 6. 막히면?
연동 중 화면이 이상하거나 답이 예상과 다르면, **그 요청과 응답을 그대로 캡처해서** 원석님께 보내면 됩니다. 백엔드에서 바로 맞춰줄 수 있어요.
