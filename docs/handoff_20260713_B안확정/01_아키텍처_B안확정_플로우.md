# 01. 아키텍처 — 방향성 B안 확정 & 데이터 플로우

## 1) B안이란 (팀 채택, 7/12 회의 → 7/13 최종 확정)

> "비결정성(같은 학생인데 추천이 매번 다름)을 숨기지 말고, **여러 전략을 방향으로 제시해 유저가 고르게** 한다. 단, 방향 분류는 **규칙**이 하고, AI는 이름·설명·과목선택만."

| 안 | 내용 | 판정 |
|---|---|---|
| A안 | 방향 선택 때마다 후보 전부 실시간 분석·재생성 | ❌ 배제(무거움·비결정성 재발) |
| **B안** | 이미 분석한 특성으로 **방향을 사전 제시**, 유저 선택. 방향축=규칙, AI=설명 | ✅ **채택** |

## 2) ⚠️ 올바른 플로우 (가장 중요 — 오해 주의)

**흔한 오해 (A안, 하지 말 것)**:
```
방향 선택 → FE → BE → Gemini live 호출 → 추천 → BE → FE → UI   (방향 누를 때마다)
```
이건 배제된 A안이며 다음을 위반한다:
- **원칙 2 위반**: 발표 중 실시간 AI 호출 금지(캐싱 재현). 탭 누를 때마다 호출 = 발표 중 네트워크 사고 리스크.
- **비결정성 재발**: 같은 방향 다시 눌러도 결과가 달라짐 → 방향성 기능이 없애려던 문제를 되살림.
- **속도·쿼터**: 탭마다 2~4초 지연, 프리티어 15 RPM 금방 소진.

**확정된 B안 플로우 (이대로 구현)**:
```
[최초 1회]  진단 완료 → POST /profiles/{id}/recommendations
  ├ BE 규칙: 후보축소(182과목 → ~16개)
  ├ BE 규칙: 후보를 5방향으로 분류 (+ 가드 + caution 결정)
  ├ Gemini live 1회: 방향별 후보를 한 번에 전달 → 방향별 과목 pick + 이유②③
  └ 결과(5방향 전부 + 이유3개)를 캐시에 저장

[방향 탭 선택]  FE가 이미 받은 directions[] 중 해당 항목만 화면에 표시
  ★ BE·AI 왕복 없음 ★ → 즉각 전환, 항상 동일, 발표 안전

[재접속/발표]  GET /profiles/{id}/recommendations → 캐시 반환
```

핵심: **AI는 최초 1번만** 부르고 그 안에 5방향이 다 들어있다. 방향 선택은 프론트에서 표시만 바꾼다. UX("방향 고르면 그 방향 과목이 뜬다")는 동일, 왕복이 없어 빠르고 재현 가능.

→ 따라서 **"FE가 BE에 어떤 방향 골랐는지 알려주는" 단계는 B안에서 불필요**(인서 작업 감소). 방향 선택값을 BE로 보내는 건 분석 로깅 목적이 아니면 안 한다.

## 3) 규칙 vs AI 경계 (원칙 1 유지)

| 담당 | 항목 |
|---|---|
| **규칙(결정적, 항상 동일)** | 졸업진단·부족요건·후보축소·**방향 분류**·**caution 경고**·이유①(성향맞춤)·가드·폴백 |
| **AI(변동, 1회)** | 방향별 어떤 과목 5개를 고르나 + 이유②(특성)·이유③(졸업기여/전공) |

## 4) 원석 확정 결정 2건 (이 세션)

- **5방향 전부 노출**: 3탭 축소안 대신 5개 모두 노출. 단 **가드는 유지** — 방향별 매칭 과목이 5개 미만이면 규칙 top5로 채우고, 그래도 부족하면 카드 수를 줄이고 "이 방향에 맞는 과목이 적어요" 안내(빈 탭 방지). 5개를 노출하되 얇은 방향도 숨기지 않는다.
- **편향 경고(빨간 글씨)**: 편향이 심한 방향(④시험형·⑤협업형)에 경고를 표시. 단 문구는 FE 하드코딩이 아니라 **BE가 `caution` 필드로 내려주고 FE는 값 있으면 빨간 글씨 렌더**. "규칙이 판단, AI는 설명" 유지 + 편향 방향 변경 시 FE 수정 불필요.

## 5) 결합 방식 = A(개인화) 확정

방향 선택 후, 그 방향 **내부에서** 성향(profile.py: 개별형/협업형)으로 정렬 + 이유①을 개인화. 시스템이 방향을 자동 추천(B)하지 않음 → 오판 시 신뢰 저하 회피, 뼈대 가벼움 유지.

## 6) 컷 라인 (막히면 순서대로 축소)

```
④⑤ 방향 → 성향 정렬 개인화(이유①은 유지) → directions 자체
  → directions 컷 시: 최상위 recommendations만 서빙 = 기존 단일 추천, FE 탭 1개
```
