너는 PassPort 프로젝트(졸업요건 진단·AI 과목 추천)의 BE 작업자다. 첨부 핸드오프 세트(00~07)와 MASTER/부록을 숙지하고 아래를 **순서대로** 진행한다. 한 단계 완료 → 무엇을 어떻게 바꿨는지 보고 → 내 확인 후 다음.

## 진행 규칙
1. 확정 아키텍처 = **B안**: AI는 최초 POST 때 1회만 호출, 5방향 결과를 모두 생성·캐시. 방향 선택은 프론트 처리(BE 왕복 없음).
2. 확정 결정: **5방향 전부 노출 + 가드 유지**, **편향(④⑤)은 `caution` 필드로 경고**, **결합 A(개인화)**, **최상위 recommendations 미러 유지(하위호환)**.
3. 사실 판정은 규칙, AI는 과목선택+이유②③만. 검증된 근거 없는 값 창작 금지 — 모르면 "⚠️ 확인 필요"로 남기고 나에게 물어라.
4. 응답 `{success, data, message}`. reasons 3개 배열. 계약은 02 문서가 SSOT.
5. **환경 제약**: 기존 파일 수정은 Edit/Write(이 폴더는 정상). git 쓰기는 bash 금지 — 내가 Windows 네이티브로 직접. `gradlew test` 금지 → 검증은 서버 기동 후 curl. `.env`는 절대 만지지 않는다.
6. 에러 시 코드 수정보다 원인 분석 먼저. 커밋 전 diff 요약 제시(커밋은 내가 실행).

## STEP A — 현행 확인

## STEP B — passport-ai directions 확장 (Python, 로컬 수정)
02 문서 §B의 설계대로:
1. `core/directions.py` 신설 — 5방향 분류 100% 규칙 + 가드 + caution(④⑤). 이름·설명·caution은 규칙 템플릿 고정.
2. `core/models.py` — `Direction` dataclass, `Result`에 `directions`·`defaultDirectionId`, `to_dict()` v2.
3. `core/prompt.py`·`gemini.py` — AI 1회 유지, 출력 스키마 `{directions:[{directionId, items:[{courseCode, reason2, reason3}]}]}`, response_schema 강제, temperature 0.3.
4. `core/validate.py` — 방향별 검증, 유효 5개 미만이면 규칙 top5 보충, 이유①=profile 성향(결합 A).
5. `core/fallback.py`·`cache.py` — 방향별 규칙 top5 폴백, 캐시 v2 포맷.
6. `core/recommend.py` — 방향 오케스트레이션(02 문서 의사코드).
7. 검증: **폴백 먼저** `python batch.py demo` → 방향별 5개·이유 3개·가드 확인 → **데모 학생 202312345는 MAJOR_DEEP이 가드로 얇아지는지 확인** → 그다음 live.
