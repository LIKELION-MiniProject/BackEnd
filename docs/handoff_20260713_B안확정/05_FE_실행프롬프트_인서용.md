# 05. FE — 인서 설명 스크립트 & 구현 프롬프트

## A. 인서에게 말할 설명 스크립트 (구어체, 그대로 복붙 가능)

> 인서야, AI 추천 방향성 기능 계약 공유할게. 세 가지만 기억하면 돼.
>
> **1) 방향 탭 전환은 프론트에서 처리해. 백엔드 다시 안 불러도 돼.**
> 추천 요청 한 번(`GET /api/v1/profiles/{id}/recommendations`) 하면 응답 안에 `directions` 배열로 방향 5개가 **각각의 추천 과목까지 통째로** 들어와. 사용자가 탭 누르면 그 배열에서 해당 방향 꺼내서 카드만 다시 그리면 끝이야. AI는 처음에 한 번만 돌아서 결과가 캐시에 저장돼 있어. 그래서 서버 왕복이 없고, 즉각 전환되고, 발표 때도 안전해. 방향 선택값을 서버로 보낼 필요도 없어(그만큼 네 일이 줄어).
>
> **2) 화면 구성은 응답 그대로 따라가.**
> 탭은 `directions` 순서·개수대로 렌더(최대 5개). 처음 활성 탭은 `defaultDirectionId`. 각 방향 객체에 `name`(탭 라벨), `description`(방향 설명), `recommendations`(과목 카드 5장: courseName·credit·reasons 3줄)가 들어 있어.
>
> **3) `caution` 필드가 핵심이야.**
> 각 방향에 `caution`이 있는데, **`null`이면 아무것도 안 띄우고, 문자열이 있으면 방향 라벨 아래에 빨간 글씨로 그 문구를 그대로 출력**해줘. 편향이 심한 방향(시험형·협업형)에만 서버가 경고를 채워 보내. 문구는 서버가 주니까 하드코딩하지 마 — 나중에 편향 방향 바뀌어도 네 코드 안 고쳐도 되게 한 거야.
>
> 상태는 4종(정상 / `source`가 "fallback"이면 "기본 추천" 배지 / 로딩 / 빈·에러)만 신영 화면요청 기준으로 잡아줘. 서버 없이 작업할 수 있게 **live/cache/fallback 목업 JSON 3종을 오늘 중 전달**할게. 그거 `src/mocks/`에 넣고 화면부터 만들면 돼. 기술스택 React+Vite 기준으로 컴포넌트 나눠서(04 문서 구조 참고) 진행하면 됩니다.

## B. 인서 세션에 붙여넣을 구현 프롬프트 (선택)

(★ 여기부터 복사 ★)

너는 PassPort의 프론트엔드(React + Vite) 개발을 돕는다. AI 분석 페이지를 아래 계약과 디자인 시안 기준으로 구현한다.

## 계약 (BE 제공, 변경 금지)
GET `/api/v1/profiles/{id}/recommendations` → `{ success, data, message }`.
`data` = `{ recommendations[], directions[], defaultDirectionId, source, generatedAt }`.
- `directions[]`: `{ directionId, name, description, caution, recommendations[] }`.
- `recommendations[]`(방향 안): `{ courseCode, courseName, credit, reasons[3] }`.
- 규칙: 탭=directions 순서·개수대로, 기본선택=defaultDirectionId, **caution!=null이면 라벨 아래 빨간 글씨**, source=="fallback"이면 "기본 추천" 배지.
- **방향 전환은 클라이언트 상태로만. 서버 재호출 없음.**

## 작업
1. `src/mocks/`에 live/cache/fallback JSON 3종 배치(BE 전달본).
2. `pages/AiAnalysis.jsx` + `components/DirectionTabs.jsx`·`RecoCard.jsx`·`StatSummary.jsx`(선택)·`Badge.jsx`·`States.jsx`.
3. 선택 directionId는 `useState`, 기본값=defaultDirectionId. 활성 방향의 recommendations를 카드로.
4. caution 빨간 글씨, source==fallback 배지, 로딩/빈·에러 상태.
5. `api/recommendations.js`에 fetch 래퍼(Authorization: Bearer). 초기엔 목업 import, 이후 실서버 교체.
6. 디자인 시안(신영 PNG): 사이드바 + 헤더 "AI 분석" + 우상단 초록 배지 + (변형) 상단 통계 카드 + 방향 탭 + 카드5(이유 3칩: 파랑·파랑·노랑). 라벨 문구는 PNG 기준.

목업으로 화면 완성 → 서버 준비되면 fetch로 교체. 컴포넌트 단위로 커밋.
