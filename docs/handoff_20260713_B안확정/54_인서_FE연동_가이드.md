# FE 연동 가이드 (인서님용) — PassPort 프론트 ↔ 백엔드

> 안녕하세요 인서님! 백엔드가 계약대로 다 준비돼서, 이제 프론트를 **목업 → 실 서버**로 연결하는 단계예요. 아래 순서대로만 하면 됩니다. 궁금한 건 편하게 물어봐 주세요.
> 백엔드 실행: `gradlew bootRun` (포트 8080). CORS는 5173·5174 둘 다 열어놨어요.

---

## 0. 먼저 알아둘 3가지 (공통 규칙)

1. **모든 응답은 `{ success, data, message }` 봉투에 담겨 옵니다.** 성공이면 `message=null`, 실제 값은 `data` 안에. → 아래 `client.js`가 이걸 자동으로 벗겨줘요.
2. **로그인 후 받은 토큰을 모든 요청 헤더에 `Authorization: Bearer <token>`** 로 넣어야 합니다(회원가입·로그인 빼고 전부).
3. **AI 추천만 동작이 특별해요**: "분석하기"(POST)는 데이터가 바뀌었으면 **실시간 AI 재분석(5~6초)**, 안 바뀌었으면 즉시 캐시. 조회(GET)는 마지막 결과. → **로딩 UI가 꼭 필요**합니다(6단계 참고).

## 1. API 클라이언트 + 토큰 (제일 먼저)

```js
// src/api/client.js
const BASE = "/api/v1";

export async function api(path, { method = "GET", body, token } = {}) {
  const res = await fetch(BASE + path, {
    method,
    headers: {
      "Content-Type": "application/json; charset=utf-8",
      ...(token && { Authorization: `Bearer ${token}` }),
    },
    ...(body && { body: JSON.stringify(body) }), // fetch는 UTF-8이라 한글 OK
  });
  const json = await res.json(); // { success, data, message }
  if (!res.ok || !json.success) throw new Error(json.message || `HTTP ${res.status}`);
  return json.data; // 껍데기 벗긴 data만 반환
}
```
- 토큰은 로그인 성공 시 저장(localStorage 등 팀 정책). 401 뜨면 로그인 화면으로 보내면 돼요.
- Vite 개발 프록시(선택): `vite.config.js`에 `server.proxy = { "/api": { target: "http://localhost:8080", changeOrigin: true } }`.

## 2. 로그인 / 회원가입 → 온보딩 분기

| 호출 | 요청 body | 응답 data |
|---|---|---|
| `POST /auth/signup` | `{ email, password(8자↑), nickname }` | `{ id, email, nickname }` |
| `POST /auth/login` | `{ email, password }` | `{ accessToken, tokenType:"Bearer", userId, nickname }` |
| `GET /auth/me` | (토큰) | `{ id, email, nickname, profileId }` |

```js
const login = await api("/auth/login", { method:"POST", body:{ email, password } });
saveToken(login.accessToken);
const me = await api("/auth/me", { token: getToken() });
// ★ me.profileId === null → 프로필 생성(온보딩)으로, 아니면 대시보드로
```

## 3. 프로필 최초 생성 화면 (신규 유저용 — 현재 미구현, 추가 필요)

`me.profileId`가 `null`인 신규 유저는 요건·수강·추천을 쓰기 전에 **프로필부터** 만들어야 해요.

```js
const prof = await api("/profiles", { method:"POST", token,
  body:{ deptCode:"BIGDATA_AI", studentId:"20250001", admissionYear:2025, name:"홍길동" } });
// prof.id 를 이후 모든 /profiles/{id}/... 에 사용. AuthContext에 profileId로 저장.
```
> `deptCode`는 현재 `"BIGDATA_AI"` 하나예요(학과 하드코딩).

## 4. 데이터 입력 화면 → 실 API

### 졸업요건 (사진1)
- `GET /profiles/{id}/requirements` → 저장값 또는 기본값(+`source: "user"|"default"`).
- `PUT /profiles/{id}/requirements` ← 같은 구조. `draft:true`면 임시저장(검증 완화), `draft:false`면 5개 영역 등 필수검증.
```jsonc
{
  "credits": { "total":130, "majorRequired":0, "majorElective":0, "majorBasic":0,
    "liberalRequired":0, "liberalElective":0, "majorTotal":70, "liberalTotal":30,
    "teaching":0, "generalElective":0, "external":0, "doubleMajor":0, "minor":0,
    "linkedMajor":0, "convergenceMajor":0 },
  "requiredCourseType": "교필",                 // "교필" 또는 "전필"
  "coreLiberal": [ { "areaNo":1, "areaName":"언어와 문학", "courseCount":1, "credit":2, "target":true }, /* …5개 */ ],
  "certification": { "foreignLangCert":"대상", "infoProcessing":"비대상", "cpr":"완료",
    "socialService":"완료", "foreignLangExtra":"비대상" },   // 값: 대상 / 비대상 / 완료
  "graduationExam": "EXAM",                    // EXAM / EITHER / THESIS / NONE
  "draft": false
}
```

### 수강 내역 (사진2) — 성적 입력
- `POST /profiles/{id}/courses` (과목 1건씩), `GET`(목록), `PUT/DELETE`(수정/삭제).
```jsonc
{ "name":"데이터베이스", "credit":3, "category":"MAJOR_ELECTIVE",
  "grade":"A+", "year":2025, "semester":1, "retake":false }
```
- `category` enum(그대로 문자열): `MAJOR_REQUIRED` / `MAJOR_ELECTIVE` / `MAJOR_BASIC` / `GE_REQUIRED` / `GE_ELECTIVE` / `GENERAL_ELECTIVE`.
- `grade`: `"A+","A","B+","B",…,"F","P","NP"` (A0/B0 입력해도 서버가 A/B로 정규화). 조회는 flat 목록 → 화면에서 학기별 그룹핑.
- ⚠️ 내장 예시 과목명(대학영어 등)은 지우고 실제 입력/서버값으로.

## 6. ⭐ AI 분석 연동 (여기가 제일 중요 — 동작이 특별함)

### 규칙
- **"AI 분석하기" 버튼 → `POST /profiles/{id}/recommendations`**: 성적·요건·자격증이 하나라도 바뀌었으면 **실시간 재분석(5~6초)**, 안 바뀌었으면 즉시 캐시 반환. → **로딩 표시 필수.**
- **페이지 재방문 → `GET /profiles/{id}/recommendations`**: AI 호출 없이 마지막 결과.
- **방향 탭 전환·비교는 프론트에서** 처리(서버 재호출 없음) — 응답 하나에 방향이 다 들어있어요.

### 응답 구조 (`data`)
```jsonc
{
  "recommendations": [ /* 기본방향 미러(하위호환) */ ],
  "directions": [
    { "directionId":"FAST_GRAD", "name":"졸업요건 집중형", "description":"…",
      "caution": null, "thin": false,
      "recommendations": [
        { "courseCode":"…", "courseName":"…", "credit":3, "category":"전공선택",
          "reasons":["성향 맞춤","과목 특성","졸업·전공 기여"] }   // 순서 고정
      ] }
  ],
  "defaultDirectionId": "FAST_GRAD",
  "source": "live",         // live | cache | fallback
  "generatedAt": "…"
}
```

### 렌더 규칙
- 탭 = `directions[]` 순서·개수 그대로, 기본 선택 = `defaultDirectionId`.
- `caution`: `null`이면 표시 안 함, 문자열이면 **탭 아래 빨간 글씨** 그대로 출력(문구는 서버가 줌 — 하드코딩 금지).
- `thin: true`: 그 방향 과목이 적음 → 카드가 적게 나오고 "이 방향에 맞는 과목이 N개예요" 안내(빨간 caution과 겹치지 않음).
- 카드 = `courseName` + `category · credit학점` + `reasons[0]`(성향)·`reasons[1]`(특성)·`reasons[2]`(졸업·전공) 칩 3개.
- `source === "fallback"` → 상단에 **"기본 추천" 배지**(AI 실패 시 규칙 추천).

```js
async function analyze(profileId, token) {
  setLoading(true);
  try {
    const data = await api(`/profiles/${profileId}/recommendations`, { method:"POST", token });
    setReco(data);
    setActiveDir(data.defaultDirectionId);
  } catch (e) { setError(e.message); }
  finally { setLoading(false); }
}
// 탭 전환은 재호출 없이: const active = reco.directions.find(d => d.directionId === activeDir);
```

### ⚠️ 꼭 알아둘 두 가지
1. **로딩 6초**: POST는 실시간 분석이라 몇 초 걸려요. "분석 중이에요…" 스켈레톤/스피너(신영님 디자인, 문서 29b) 반드시. 한 번 받은 결과는 상태에 담아 탭 전환 시 재호출 안 하기.
2. **실데이터는 지금 방향이 2개(빠른졸업·전공심화)만** 나옵니다(핵심교양 영역 매핑이 아직 없어서). 데모 계정은 4방향. 화면은 `directions[]` 길이만큼 렌더하면 자동 대응돼요.

## 7. 상태 4종 + 마무리 (7/15 게이트 기준)

| 상태 | 조건 | 표시 |
|---|---|---|
| 로딩 | 요청 중 | 스켈레톤/스피너 |
| 정상 | `source` live/cache | 초록 "AI 분석 완료" + 결과 |
| 기본 추천 | `source==="fallback"` | 앰버 "기본 추천" 배지 |
| 빈·에러 | 실패/빈 배열 | 안내 + [다시 시도] |

**E2E 관통 1회**(게이트 통과 조건): 로그인 → (프로필 생성) → 요건 → 수강 → 대시보드 → AI 분석 → 결과 표시.
