## 4. 🔴 반드시 알아야 할 함정

### ① `batch.py`로 실데이터 캐시를 만들 수 없다

```python
{"demo": cmd_demo, "candidates": cmd_candidates, "models": cmd_models}.get(cmd, cmd_demo)()
```
모르는 인자는 **전부 demo로 조용히 폴백**. 82·85의 `python batch.py {학번}` 절차는 **실행 불가능**이었다.
🔴 **실데이터 캐시는 `POST /recommendations`가 유일 경로.**

### ② 지문(fingerprint)에 카탈로그가 없다

- 지문 = **유저 입력 데이터**(수강·요건·인증·프로필)만. **`courses.json`을 고쳐도 캐시가 재생성되지 않는다.**
- 강제 재생성: `rm -f cache/{학번}.json cache/{학번}.fp` → POST 1회. 🔴 **`.fp`만 지우면 안 된다**("캐시 유지 + 지문만 기록" 분기에 걸림).
- **지문은 Java측**([`RecommendationService.fingerprint()`](../../src/main/java/com/passport/recommendation/service/RecommendationService.java))에서 생성. **`c.getCredit()`을 문자열로 붙이므로 `credit`이 double이 되며 `3` → `3.0`으로 바뀌어 7/16에 기존 지문이 전부 무효화됐다**(의도된 부수효과, 재생성 완료).

### ③ directions는 특성 데이터가 없으면 사라진다

`classify()`의 `if not matched: continue`.

| 방향 | 필터 | 특성 의존 |
|---|---|---|
| `FAST_GRAD` / `MAJOR_DEEP` | 영역·학점·카테고리 | ❌ |
| `GRADE_SAFE` | `gradingStyle=="너그러움"` **and** 시험≠많음 **and** 팀플≠많음 | ✅ |
| `EXAM_SOLO` | 시험∈(많음,보통) **and** 팀플∈(없음,None) | ✅ |
| `TEAM_ACTIVE` | 팀플∈(보통,많음) **or** 발표∈(보통,많음) | ✅ |

`MIN_PER_DIRECTION = 5` 미만 → `thin=true`. `MAX_PER_DIRECTION = 5`. `caution`은 `EXAM_SOLO`·`TEAM_ACTIVE` 전용, thin 방향엔 안 넣음.

### ④ persona 산출 조건

1. **과목명이 `courses.json`과 정확 일치** (exact match, 공백 트림만)
2. **매핑된 과목에 평가특성이 있어야** 함 (3과목 이상에서 `balanced` 전환 확인)

둘 중 하나라도 안 되면 `EXPLORING`(탐색형). 카탈로그에 없는 과목명은 **조용히 제외**(에러 아님, 진단엔 영향 없음).

### ⑤ `source=fallback` 조건 (폴백 배지)

- `live` : AI 유효 항목 ≥ `MIN_AI_VALID`
- `fallback` : AI 유효 부족 **또는** AI 예외 + **캐시 없음**
- AI 예외 + 캐시 있음 → **캐시 반환**(원래 source 유지)

🔴 **정상 상태에서 POST하면 `live`가 떠서 배지가 안 보인다.** 폴백 시연은 `.env` 임시 리네임 필요:

```bash
mv ~/app/passport-ai/.env ~/app/passport-ai/.env.bak
# → 시연 후 반드시 복구
mv ~/app/passport-ai/.env.bak ~/app/passport-ai/.env
```
🔴 **복구를 잊으면 이후 모든 AI 호출이 폴백된다.**

### ⑥ API 400 유발 요인 (7/16 갱신)

## 6. 🔬 GRADE_SAFE thin — 왜 못 고치는가 (7/16 조사 결론)

**결론: 데이터 보강으로 해결되지 않는다. 방향 필터·정렬의 재설계가 필요하고, 그건 제출 전 범위 밖이다.**

### 시도한 것과 결과

| 안 | 내용 | 결과 |
|---|---|---|
| **B** | `MAX_CANDIDATES` 20 → 25 | ✅ **채택.** GRADE_SAFE **1 → 3**. 다른 4방향 불변. 커밋 `34afac4` |
| **C** | 후보 매칭에 교양 3종 추가 + 구분별 쿼터 | ❌ **폐기.** 시뮬레이션으로 배포 전 차단 |

### C를 폐기한 이유 (구현까지 했다가 되돌림)

매핑·쿼터를 다 구현해 **교양 14개를 후보에 넣는 데는 성공**했으나:

1. **후보에 든 교양 14개 중 GRADE_SAFE 조건 만족이 0개**
   `작가와문학세계`(너그러움)조차 시험=많음이라 탈락. 나머지는 `후함=보통` 또는 특성 없음.
2. **전부 0~2학점이라 학점 내림차순 정렬에서 3학점 전공에 항상 밀림**
   [`directions.py:88`](../../passport-ai/core/directions.py) `_lacking_first_key = (lackingArea 우선, -credit)` 인데 **`lackingAreaNos`가 항상 빈 배열**이라 사실상 `-credit`만 작동.
3. **오히려 손해**: 전공 쿼터(8)가 `자료구조`·`소프트웨어공학`을 후보에서 밀어내 **EXAM_SOLO·TEAM_ACTIVE 구성이 나빠짐.**

**결과: 5방향 전부 여전히 전공만. 순 손해.**

### 왜 `lackingAreaNos`가 빈 배열인가

[`RecommendationService.java:141`](../../src/main/java/com/passport/recommendation/service/RecommendationService.java) — `diagnosisPart.put("lackingAreas", List.of())`.
Spring 진단에 **과목↔핵심교양 영역 매핑 데이터가 없어 계산 불가**(문서 51 §7에 기록된 기존 한계). 그래서 `candidates.py`의 **1순위(교양) 경로가 통째로 죽어 있다.**

### 교양 추천이 안 되는 게 버그인가?

**아니다.** 원석 부족 학점은 **전공 42 vs 교양 14**로 전공이 3배 크다. 전공 위주 추천은 합리적 우선순위다.
문제는 **자유선택 35** 하나인데, 이건 **대응 과목군이 카탈로그에 아예 없어서**(자유선택 = 다른 요건 초과분이 흘러드는 구분) C를 해도 못 채운다. → **§3 STEP D 예상질문 답변 참조.**

### 백로그 (제출 후)

- `lackingAreas` 계산 — 과목↔영역 매핑 데이터 확보 필요
- 방향별 정렬·쿼터 재설계 (교양 노출)
- `EffectiveRequirement.coreLiberalTargetCount` — 7/16 오표시 수정으로 **소비처 없는 죽은 필드**가 됨(record 시그니처 변경 위험이 이득보다 커서 유지)
- `requiredCourse`의 `status="진행중"` — 총 필수과목 수를 몰라 `required=null`인데 "진행중"이라 단정 (근거 약함)
- `application-prod.yml` 신설 + `/h2-console/**` permitAll dev 전용 분리 (87 #2)
- `batch.py` argparse — 모르는 인자는 에러 (87 #1)
- `DiagnosisService` `fulfilled` 네이밍 — "졸업을 막지 않음"인데 FE가 체크표시로 오독하기 쉬움
- 82 §4 트랜잭션 격리
