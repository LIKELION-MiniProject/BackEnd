## 1. 【인서님】 FE 설정 — 순서대로

### 1-1. VS Code 열고 프론트 폴더 열기

1. **VS Code** 실행
2. 상단 메뉴 **`파일(File)` → `폴더 열기(Open Folder)`**
3. **프론트엔드 저장소 폴더** 선택 (안에 `package.json`이 있는 폴더)
4. 왼쪽 탐색기에 `src`, `package.json`, `vite.config.js` 등이 보이면 제대로 연 것

### 1-2. ⚠️ 시작 전 30초 — 지난번 연동 잔재 점검

> 지난번 **원석 개인 PC 서버**로 연동을 시도하다 실패했다. 그 흔적이 남아 있으면 오늘 헛다리를 짚는다. **4개만 확인하고 시작.**

| # | 점검 | 방법 |
|---|---|---|
| 1 | **옛 서버 주소 잔재** 🔴 최우선 | VS Code에서 **`Ctrl + Shift + F`**(전체 검색) → `:8080` 검색 → `vite.config.js`·env 파일·코드에 **하드코딩된 주소**가 있으면 제거/교체. **코드에 직접 박힌 주소는 아래 `.env.local`을 무시한다** |
| 2 | **브라우저의 옛 토큰** | EC2는 JWT 서명키가 새로 생성돼 **옛 토큰이 전부 무효**다. Chrome **F12** → **`Application`** 탭 → 왼쪽 **`Local Storage`** → 항목 삭제 (401 무한루프 오판 방지) |
| 3 | **목업/우회 코드** | 접속 실패 시절 넣은 목업 폴백·임시 주석이 있으면 제거. 연동 성공 판별은 반드시 **Network 탭의 실제 요청 URL**로 |
| 4 | **옛 테스트 계정** | 그때 만든 계정은 원석 PC에만 있다. **EC2는 새 DB** — 아래 계정을 쓸 것 |

### 1-3. `.env.local` 파일 만들기 (이게 핵심)

1. VS Code 왼쪽 탐색기에서 **최상위**(=`package.json`이 있는 줄) 빈 공간에 **마우스 우클릭**
2. **`새 파일(New File)`** 클릭
3. 파일명 입력 → **`.env.local`**
   - ⚠️ **앞에 점(`.`)이 있고, 확장자는 없다.** `env.local`(점 없음)이나 `.env.local.txt`는 안 된다
4. 파일이 열리면 **아래 한 줄**을 입력:

```
VITE_API_BASE_URL=http://15.164.84.176:8080/api/v1
```

5. **`Ctrl + S`** 저장

> **왜 `.env.local`인가**: 이 파일은 보통 `.gitignore`에 들어 있어 **git에 커밋되지 않는다.** `vite.config.js`를 고치면 커밋 대상이라 게이트 후 원복을 잊기 쉽다.

### 1-4. dev 서버 재시작 (필수)

> ⚠️ **환경 파일은 재시작해야 읽힌다.** 저장만 하고 새로고침하면 반영 안 된다.

1. VS Code 상단 메뉴 **`터미널(Terminal)` → `새 터미널(New Terminal)`**
2. 이미 dev 서버가 돌고 있으면 그 터미널에서 **`Ctrl + C`** (중지)
3. 아래 입력 후 Enter:

4. `Local: http://localhost:5173` 같은 줄이 나오면 성공

```bash
sudo systemctl status passport --no-pager
```

→ **`Active: active (running)`** 확인

### 2-4. 로그 흘려놓기 (게이트 끝까지 유지)

```bash
sudo journalctl -u passport -f
```

인서님이 로그인/조회할 때마다 **실시간으로 요청이 보인다.** 이 창은 그대로 둔다.

- 멈추려면 `Ctrl + C`
- persona 브릿지만 보고 싶으면:
```bash
sudo journalctl -u passport -f | grep --line-buffered "persona 브릿지"
```

### 2-5. 에러가 나면

로그의 **에러 줄을 그대로 복사해서 공유**. FE 문제인지 BE 문제인지 즉시 갈린다.
- **로그에 요청이 찍힘** → 서버까지 도달 → BE 또는 데이터 문제
- **로그에 아무것도 안 찍힘** → 요청이 서버에 도달 못함 → FE 설정 또는 네트워크 문제

### 구현 시 주의

- 🔴 **버튼 클릭 시 로딩 상태 필수** — 재분석은 **수 초** 걸린다(Gemini 호출)
- ✅ **변동이 없으면 즉시 응답한다. 로딩이 안 보이는 게 정상**이다 (버그 아님)
- ❌ **화면 진입 시 POST를 부르면 안 된다** — 조회는 반드시 `GET`

### 응답 계약 (이미 확정·반영됨)

```
directions[]        방향 탭 (현재 5개)
  ├─ directionId    FAST_GRAD | MAJOR_DEEP | GRADE_SAFE | EXAM_SOLO | TEAM_ACTIVE
  ├─ name           졸업요건 집중형 | 전공 심화형 | 학점 안정형 | 시험·개별평가형 | 협업·활동형
  ├─ thin           true면 "이 방향에 맞는 과목이 적어요" 박스
  ├─ caution        편향 경고 문구 (EXAM_SOLO·TEAM_ACTIVE 전용, null 가능)
  └─ recommendations[]
       ├─ courseCode / courseName / credit / category
       └─ reasons[3]   순서 고정: 성향 → 특성 → 졸업기여
defaultDirectionId  기본 선택 탭 (FAST_GRAD)
persona             { type, label, description, strategies[3], summary[3] }
source              "live" | "fallback"  ← "fallback"일 때만 "기본 추천" 배지
```

**현재 원석 계정의 실제 값** (인서님이 화면에서 볼 것):

| 방향 | 과목 수 | thin | caution |
|---|---|---|---|
| 졸업요건 집중형 (기본) | 5 | — | — |
| 전공 심화형 | 5 | — | — |
| **학점 안정형** | **1** | **✅ thin 박스** | — |
| **시험·개별평가형** | 5 | — | **✅ "시험 비중이 높아 시험 부담이 클 수 있어요."** |
| **협업·활동형** | **3** | **✅ thin 박스** | — |

persona = **`균형 성장형`(BALANCED)**

- **학기 GPA 필드명** : `dash.semesterGpa` (누적 GPA와 **다른 값**이다 — 현재 학기 3.7727 vs 누적 3.8158)

## 5. 에러 대응표

| 증상 | 원인 → 조치 |
|---|---|
| 요청이 계속 **`localhost:8080`** 으로 감 | dev 서버 재시작 안 함 → `Ctrl+C` 후 `npm run dev` |
| 요청이 **옛 IP**로 감 | 코드에 주소 하드코딩 → `Ctrl+Shift+F`로 `:8080` 검색해 제거 |
| 콘솔에 **CORS 에러** | `localhost:5173`이 아닌 주소에서 페이지를 엶 → `http://localhost:5173`으로 접속 |
| **Mixed Content 차단** | https 페이지에서 http API 호출 → `http`로 접속 |
| **401 무한루프** | 옛 JWT 토큰 → F12 → Application → Local Storage 삭제 |
| 로그인은 되는데 **화면이 비어있음** | `demo1`으로 로그인함(프로필 없음, `profileId: null`) → `songwonseok1234@...`로 로그인 |
| **추천이 2방향만 나옴** | 캐시가 특성 보강 이전 상태 → 원석에게 알릴 것 (86 §2 절차로 재생성) |
| **persona가 "탐색형"** | 과목명이 카탈로그 정확명과 불일치 → 86 §6 |
| **서버가 응답 없음** | 원석: `sudo systemctl status passport` → 죽었으면 `sudo systemctl restart passport` |

## 6. ⚠️ 리허설 시 반드시 1회 — 재분석 경로

시연 하이라이트가 **"과목 추가 → AI 분석 버튼 → Gemini 재분석"**이다. **이 경로를 리허설에서 반드시 1회 실행해야 한다.**

**이유**: 과목을 추가하면 지문이 바뀌어 **실제로 Gemini가 재분석**한다. 그 결과의 **방향 수·persona가 달라질 수 있다**(추가한 과목의 특성에 따라). 시연에 적합한지 미리 봐야 한다.

| 확인 | 내용 |
|---|---|
| 재분석 후 **방향이 5개를 유지**하는가 | 줄어들면 시연 임팩트 하락 |
| **persona가 유지**되는가 | `균형 성장형` → 다른 값으로 바뀌어도 무방하나 설명 준비 필요 |
| 소요 시간 | 수 초 — 로딩 표시가 제대로 나오는가 |

> 🔴 **부적합하면 시연에서 ⑤를 설명으로 대체**하고 기록. (지시서 STEP A-4)
> 🔴 **리허설에서 추가한 과목은 그대로 남는다.** 시연 전 삭제할지 정할 것 — 삭제해도 지문이 바뀌어 재분석된다.

**추가할 과목 추천** (카탈로그 존재 + 특성 보유라 매핑이 확실):

```json

{"name":"딥러닝","credit":3,"category":"MAJOR_ELECTIVE","grade":"A","year":2026,"semester":2,"retake":false}
```
