## 1. 🔴 FE 연동 현황 — 핵심 이슈

### 확진된 문제

**FE의 수강 입력이 서버에 단 한 번도 저장된 적이 없다.**

| 확인 | 결과 |
|---|---|
| 서버 `courses` INSERT **총 횟수** | **16건** — 원석이 curl로 넣은 것뿐 |
| **FE 입력 후 INSERT** | **0건** 🔴 |
| 화면에 보이던 `과학기술과나눔` | 서버에 **없음** |
| 화면의 `통계기초 C+` | 서버는 **`A`** |

```
[성적 화면]  서버에서 GET으로 읽음 → 화면에서 수정 → ❌ 서버로 안 보냄 → 로컬 메모리에만
[홈 배너]    서버에서 GET으로 읽음 → 서버는 안 바뀜 → 39/130, 30% 고정
```

**읽기는 연동됐고(홈 배너가 서버 값과 일치), 쓰기가 미연동이다.**

### 백엔드는 문제없음 — 라이브 테스트로 증명 완료

## 2. 🔴 반드시 알아야 할 함정 (재발 방지)

> 상세는 [87 문제발견_수정내역](87_문제발견_수정내역.md) · [86 메커니즘 실측](86_캐시_persona_메커니즘_실측기록.md)

### ① `batch.py`로 실데이터 캐시를 만들 수 없다

```python
{"demo": cmd_demo, "candidates": cmd_candidates, "models": cmd_models}.get(cmd, cmd_demo)()
```
- `demo`/`candidates`/`models` 3개만 받고 **모르는 인자는 전부 demo로 조용히 폴백**
- 82·85 초판의 `python batch.py {학번}` 절차는 **실행 불가능**이었다
- 2단계의 `batch.py 202312345`가 성공해 보인 건 **demo가 돌았는데 studentKey가 우연히 같아서**였다
- 🔴 **실데이터 캐시는 `POST /recommendations`가 유일 경로**

### ② 지문(fingerprint)에 카탈로그가 없다

- 지문 = **유저 입력 데이터**(수강·요건·인증·프로필)만
- **카탈로그(`courses.json`)를 고쳐도 캐시가 재생성되지 않는다**
- 강제 재생성:
```bash
rm -f ~/app/passport-ai/cache/{학번}.json ~/app/passport-ai/cache/{학번}.fp   # 반드시 둘 다
# → POST /recommendations 1회
```
- 🔴 **`.fp`만 지우면 안 된다** — "캐시 유지 + 지문만 기록" 분기에 걸린다
- 부수 효과: **수강 과목 추가/삭제 시 지문이 바뀌어 자동 재생성**된다(의도된 동작)

### ③ directions는 특성 데이터가 없으면 사라진다

`classify()`의 `if not matched: continue` — 빈 방향은 아예 노출 안 됨.

| 방향 | 필터 | 특성 의존 |
|---|---|---|
| `FAST_GRAD` / `MAJOR_DEEP` | 영역·학점·카테고리 | ❌ 무관 |
| `GRADE_SAFE` | `gradingStyle == "너그러움"` and 시험≠많음 and 팀플≠많음 | ✅ |
| `EXAM_SOLO` | 시험∈(많음,보통) and 팀플∈(없음,None) | ✅ |
| `TEAM_ACTIVE` | 팀플∈(보통,많음) or 발표∈(보통,많음) | ✅ |

- `MIN_PER_DIRECTION = 5` 미만 → `thin=true`
- `caution`은 `EXAM_SOLO`·`TEAM_ACTIVE` 전용, **thin 방향엔 안 넣음**
- **전공 31과목 중 특성 보유는 11개뿐**(원석 Notion 데이터로 보강한 것). 다른 조합이면 방향이 줄 수 있다

### ④ persona 산출 조건

1. **과목명이 `data/courses.json`과 정확 일치** (exact match, 공백 트림만)
2. **매핑된 과목에 평가특성이 있어야** 함 — **3과목 이상**에서 `balanced` 전환 확인

둘 중 하나라도 안 되면 `EXPLORING`(탐색형). 카탈로그에 없는 과목명은 **조용히 제외**(에러 아님, 진단엔 영향 없음).

**카탈로그 정확명 주의**:
`데이터분석의기초` → **`데이터분석의기초(MD)`** / `창의적사고와코딩` → **`창의적사고와코딩(MD)`** / `인성과대학생활` → **`인성과대학생활Ⅰ`** / `인공지능플랫폼설계` → **`인공지능 플랫폼 설계`**(띄어쓰기)

### ⑤ `source=fallback` 조건 (폴백 배지)

- `live` : AI 유효 항목 ≥ `MIN_AI_VALID`
- `fallback` : AI 유효 부족 **또는** AI 예외 + **캐시 없음**
- AI 예외 + 캐시 있음 → **캐시 반환**(원래 source 유지)

🔴 **정상 상태에서 신규 계정으로 POST하면 `live`가 떠서 배지가 안 보인다.** 폴백 시연은 `.env` 임시 리네임 필요:
```bash
mv ~/app/passport-ai/.env ~/app/passport-ai/.env.bak
# → 시연 후 반드시 복구
mv ~/app/passport-ai/.env.bak ~/app/passport-ai/.env
```
🔴 **복구를 잊으면 이후 모든 AI 호출이 폴백된다.**

### ⑥ API 사용 시 400 유발 요인

| 항목 | 주의 |
|---|---|
| `grade` | 화면의 **`A0`** → 서버엔 **`"A"`**. `A+ A B+ B C+ C D+ D F P NP`만 허용 |
| `credit` | **정수만**. 0.5 불가(`int`) |
| `category` | `MAJOR_REQUIRED` `MAJOR_ELECTIVE` `GE_REQUIRED` `GE_ELECTIVE` `GENERAL_ELECTIVE` — **전공기초 없음**(→`MAJOR_REQUIRED`) |
| `PATCH /profiles/{id}` | **이름만 PATCH, 전체 필드 전송 필수**. 일부만 보내면 나머지가 `null`로 덮어써짐 |
| `PUT /courses/{cid}` | 마찬가지로 **전체 필드** |

| 4 | **`GENERAL_ELECTIVE`(자유선택) 0/35** | 부족 35학점으로 가장 크게 잡힘. **실제 을지대 요건과 일치하는지 미검증** (하드코딩값) |
| 5 | **졸업 인증 전부 `NOT_SUBMITTED`** | 어학·봉사 미충족 표시 중. 시연에서 인증 화면을 쓸 거면 `PUT /profiles/1/certifications`로 실제 상태 입력 필요 |
| 6 | 9과목 `성적후함정도` 미확보 | 확보 시 `GRADE_SAFE` thin(1과목) 해소 |
| 7 | 1학년1학기 성적 임의값 7건 | 성적조회 가능해지면 실데이터 교체 |
