# 96 — AI · 서버 안정성 리포트 (2026-07-16)

> **질문** : "AI API를 쓰면 배포할 때 서버가 터질 수 있다"는데, 우리는 무엇을 우려했고 어떻게 대비했나?
> **결론 한 줄** : **이 서버는 그 문제를 구조적으로 회피했다.** 배포·기동 시엔 AI를 아예 호출하지 않고, 호출되더라도 별도 프로세스 격리 + 타임아웃 + 폴백 + 메모리 상한으로 JVM(본 서버)을 지킨다.
> **근거** : 코드( [`PassportAiBridge.java`](../../src/main/java/com/passport/recommendation/service/PassportAiBridge.java) · [`RecommendationService.java`](../../src/main/java/com/passport/recommendation/service/RecommendationService.java) ) · 배포기록( [84](84_AWS배포_실행기록.md) ) · 라이브 응답(2026-07-16 확인).

---

## 1. 원래의 우려점

AI(Gemini) 호출을 서버에 붙일 때 일반적으로 발생하는 위험은 다음과 같다.

| # | 우려 | 왜 위험한가 |
|---|---|---|
| C1 | **메모리 부족(OOM)으로 서버가 죽음** | 작은 인스턴스에서 JVM과 AI 실행이 메모리를 동시에 먹으면 커널 OOM Killer가 프로세스를 강제 종료 → 서비스 다운 |
| C2 | **배포/기동 순간의 부하 스파이크** | 기동 직후 AI가 자동으로 돌면 초기화 부하와 겹쳐 크래시 위험 |
| C3 | **AI 호출이 멈춰(hang) 서버가 응답 불능** | 외부 API가 느리거나 자식 프로세스가 멈추면 요청 스레드가 물려 전체가 느려짐 |
| C4 | **Gemini 장애(429/503)로 기능 마비** | 쿼터 초과·일시 장애 시 추천 화면이 통째로 실패 |
| C5 | **AI 파싱 실패로 잘못된 결과 노출** | LLM 출력이 스키마와 어긋나면 깨진 응답이 사용자에게 감 |

## 2. 우리가 취한 조치 (우려별 대응)

### C1 — OOM 방지: 인스턴스 사이징 + 힙 상한 + 프로세스 격리

- **인스턴스를 t3.small(2GiB)로 선택.** t3.micro(1GiB)는 "JVM + Python 서브프로세스 동시 구동 시 OOM 위험"이라 명시적으로 배제했다. ([84 §1](84_AWS배포_실행기록.md))
- **JVM 힙을 `-Xmx1g`로 상한.** 2GiB 중 1GiB만 JVM에 주고, 나머지 1GiB를 Python·OS 몫으로 분리했다. ([84 §6-2](84_AWS배포_실행기록.md), systemd `ExecStart=/usr/bin/java -Xmx1g -jar ...`)
- **AI는 JVM 힙이 아니라 별도 OS 프로세스로 실행.** `PassportAiBridge`가 `ProcessBuilder`로 `python bridge.py`를 자식 프로세스로 띄운다. AI의 메모리 사용이 JVM 힙과 격리된다.
- **실측**: 배포 당시 메모리 **269MB / 2GiB** — 큰 여유. ([84 §6-4](84_AWS배포_실행기록.md))

### C2 — 배포/기동 시 AI 미호출

- **기동 시 자동 실행 훅이 코드에 하나도 없다.** `@PostConstruct` · `CommandLineRunner` · `ApplicationRunner` · `ApplicationReadyEvent` · `@EventListener` · `@Scheduled` 전수 검색 결과 **전무**. 배포는 JVM만 뜨는 것이고, 그 순간 AI는 돌지 않는다.
- **AI는 오직 `POST /recommendations`(="AI 분석" 버튼)에서만 호출.** `passportAiBridge.generate()`를 부르는 유일한 지점은 `RecommendationService.generate()`(POST 경로) 한 곳뿐이다. ([`RecommendationService.java:93`](../../src/main/java/com/passport/recommendation/service/RecommendationService.java))
- **조회(GET)는 캐시만 반환.** 발표 시연은 GET이라 AI를 부르지 않는다. ([`RecommendationService.java:60`](../../src/main/java/com/passport/recommendation/service/RecommendationService.java))
- **불필요한 재호출 차단(지문 캐싱).** 수강·요건·인증·프로필의 지문(fingerprint)이 이전 생성 시점과 같으면 AI를 부르지 않고 캐시를 그대로 쓴다. 데이터가 실제로 바뀐 경우에만 재분석한다.

### C3 — Hang 방지: 타임아웃 + 강제종료 + 논블로킹 스트림

`PassportAiBridge`( [코드](../../src/main/java/com/passport/recommendation/service/PassportAiBridge.java) )의 방어 로직:

| 장치 | 내용 |
|---|---|
| **60초 타임아웃** | `process.waitFor(60, SECONDS)` 초과 시 `destroyForcibly()`로 자식 프로세스 강제 종료 |
| **finally 강제 정리** | 어떤 경로로 빠지든 프로세스가 살아있으면 `destroyForcibly()` — 좀비/누수 방지 |
| **stdout/stderr 논블로킹 소비** | 별도 스레드(`CompletableFuture`)로 파이프를 빨아냄 → 버퍼가 차서 자식이 멈추는 고전적 데드락 방지 |
| **persona 브릿지도 동일** | `PersonaBridge`는 20초 타임아웃 + 폴백 (수강 변경 시 성향 재계산용) |

### C4 — Gemini 장애 대비: 캐시 폴백

- AI 실행이 실패(타임아웃·비정상 종료·파싱 실패·예외)하면 브릿지는 예외를 삼키고 **`Optional.empty()`** 를 반환한다. 호출자는 이를 받아 **캐시로 폴백**한다.
- `429/503` 등 Gemini 장애 시에도 GET은 캐시를 반환하므로 화면이 죽지 않는다. (CLAUDE.md 원칙 2 — "발표용 결과는 사전 생성·캐싱, 429/503 시 캐시로 폴백")
- 폴백 시 응답 `source=fallback` 배지로 상태를 드러낸다.

### C5 — 잘못된 결과 노출 방지

- AI 출력은 **JSON 스키마 계약(v2.1)** 으로 강제하고, 파싱 실패 시 위 C4 폴백 경로로 빠진다. 깨진 응답이 그대로 나가지 않는다.
- **사실 판정(졸업 가능·학점·GPA·요건 충족)은 AI가 아니라 규칙 기반 자바 코드가 결정**한다(CLAUDE.md 원칙 1). AI는 추천 과목 선택·이유 설명에만 관여하므로, AI가 틀려도 진단 수치는 영향받지 않는다.

## 4. 종합 판정

- **배포는 이미 완료·정상 가동 중**(오늘 라이브 로그인·요건조회·소유검증 응답 확인, systemd active/running).
- **"AI 때문에 배포 때 터진다"는 이 서버엔 해당되지 않는다.** 배포·기동 때는 AI가 돌지 않고(C2), 돌더라도 별도 프로세스(C1) + 60초 타임아웃/강제종료(C3) + 캐시 폴백(C4) + 힙 상한(C1)으로 본 서버를 지킨다.
- **잔여 확인 1건(선택)** : "지금 이 순간"의 실측 메모리는 SSH `free -h`로만 확인 가능(마지막 실측 269MB). 발표 전 리허설 때 한 번 확인 권장.
