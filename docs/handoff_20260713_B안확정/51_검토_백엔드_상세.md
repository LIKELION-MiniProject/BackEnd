## 1. 전체 엔드포인트 (`/api/v1`)
| 메서드·경로 | 권한 | 종류 |
|---|---|---|
| POST /auth/signup · /auth/login | 비회원 | 인증 |
| POST /auth/logout · GET /auth/me | 회원 | me→{id,email,nickname,profileId} |
| POST /profiles · GET/PATCH /profiles/{id} | 회원(소유) | 프로필 |
| GET·PUT /profiles/{id}/requirements | 회원(소유) | 유저 졸업요건 저장 |
| GET /requirements/{deptCode} | 회원 | 하드코딩 학과기준 |
| POST/GET/PUT/DELETE /profiles/{id}/courses | 회원(소유) | 수강(성적) |
| GET/PUT /profiles/{id}/certifications | 회원(소유) | 인증 합격여부 |
| GET /profiles/{id}/diagnosis | 회원(소유) | 규칙 진단(+5분야) |
| GET /profiles/{id}/gpa-trend | 회원(소유) | 규칙 |
| GET /profiles/{id}/dashboard | 회원(소유) | 집계(확장) |
| POST/GET /profiles/{id}/recommendations | 회원(소유) | AI 추천(캐시 서빙) |

- 인증: signup/login만 permitAll, 그 외 Bearer JWT 필수. `/profiles/{id}/**`는 `ProfileService.findOwnedProfile`로 **소유권 검증**.
- 응답 래퍼: `{success, data, message}` (성공 message=null).

## 2. 데이터/성적 입력 → 저장 → 진단 (핵심 흐름)
- **수강 입력**: `POST /profiles/{id}/courses`, 바디 `{name, credit, category(enum명), grade(라벨 "A+"등, A0/B0 별칭 허용), year, semester, retake}` → `Course`(profile N:1) H2 DB 저장(파일 영속).
  - `CourseCategory` = MAJOR_REQUIRED/MAJOR_ELECTIVE/MAJOR_BASIC/GE_REQUIRED/GE_ELECTIVE/GENERAL_ELECTIVE (JSON=enum명). `Grade` @JsonValue 라벨, P/NP GPA 제외, F는 GPA 반영·이수 미인정.
- **진단**: `GET /diagnosis` → `DiagnosisService`가 **DB의 내 과목을 읽어** 총학점·구분별·GPA·인증·**5분야**를 규칙으로 계산. 요건은 `RequirementResolutionService`(유저 저장값 우선, 없으면 하드코딩 `BigdataAiRequirement`).
- → **성적 입력이 실제로 내 DB에 저장되고 진단에 반영됨(검증 완료).**

## 3. AI 추천 (B안, 계약 v2.1) — passport-ai + Spring
### 아키텍처
- AI(Gemini) 1회로 5방향 전부 생성 → 캐시. 방향 선택/비교는 프론트. 방향분류·caution·이유①·가드·폴백=규칙, AI=방향별 과목선택+이유②③.
### passport-ai `core/`
- `candidates.py`(182→~16 후보 축소) → `profile.py`(성향) → `directions.py`(5방향 규칙 분류+가드+caution+category_label) → `prompt.py`/`gemini.py`(AI 1회, response_schema 강제, temperature 0.3) → `validate.py`(환각차단+이유①+category+규칙보충) → `fallback.py`(방향별 규칙 top5) → `cache.py`(v2 저장/조회, 구버전 호환) → `recommend.py`(오케스트레이션).
- 진입: `batch.py demo`. 모델은 `os.environ["GEMINI_MODEL"]`(.env). `requirements.txt` google-genai==1.38.0 고정.
### Spring `recommendation/`
- `RecommendationController` POST/GET, 소유권 검증, `ApiResponse`.
- `RecommendationService.resolve` = `readCache(studentId)`(cache/{studentId}.json v2를 ObjectMapper로 역직렬화) → 없으면 `ruleFallback`(진단 부족구분 top5, **과목 창작 안 함**, source=fallback).
- `CorsConfig`: origin 5173·5174, Authorization·Content-Type, allowCredentials.
- `application.yml`: `passport-ai.cache-dir: ${PASSPORT_AI_CACHE_DIR:passport-ai/cache}`.
### 계약 v2.1 (27 문서 SSOT)
```
data = { recommendations[](default 미러), directions[], defaultDirectionId, source, generatedAt }
direction = { directionId, name, description, caution, thin, recommendations[] }
item = { courseCode, courseName, credit, category, reasons[3] }
```
- reasons 순서 고정 **[성향맞춤, 과목특성, 졸업·전공기여]**. caution=EXAM_SOLO·TEAM_ACTIVE 전용, **thin이면 null**. thin=매칭<5, 개수 그대로(방향 밖 보충 금지). source=live|cache|fallback, 배지는 fallback만. cache=live 시각 동일.
- directionId 고정: FAST_GRAD/MAJOR_DEEP/GRADE_SAFE/EXAM_SOLO/TEAM_ACTIVE.

## 4. STEP E — 인증 5분야 진단 연결 (판정 규칙 검토)
- **저장**: PUT /requirements의 `certification`(foreignLangCert/infoProcessing/cpr/socialService/foreignLangExtra, 각 값 대상/비대상/완료=CertMark TARGET/NOT_TARGET/DONE) → `UserGraduationRequirement.certification`.
- **연결(신규)**: `EffectiveRequirement.certificationTargets`(유저 저장 시 값, 하드코딩 시 null) → `DiagnosisService.buildGraduationCertification()`가 판정.
- **규칙(창작 없음)**: 유저가 **대상(TARGET)**으로 표시한 분야가 전부 **완료(DONE)**여야 `fulfilled=true`. 비대상·미표기는 무시. 대학의 "5중 3/택1/필수" 규칙은 검증 데이터 없어 코드로 만들지 않음.
- **eligible 반영**: `eligible = creditsOk && certsOk && gpaOk && gradCertOk`. 유저 미저장 시 gradCertOk=true(영향 없음, 기존 동작·테스트 유지).
- **⚠️ 원석 결정 1건**: 현재 기존 인증(certsOk: LANGUAGE/VOLUNTEER/THESIS) **AND** 5분야(gradCertOk) 둘 다 요구(보수적). "5분야 저장 시 5분야만"으로 원하면 `DiagnosisService` eligible에서 `certsOk` 제거(1줄).
- 응답에 `graduationCertification{areas[5], fulfilled}` 추가(기존 `certifications[]` 유지 = 하위호환).
- **검증됨**: fulfilled false→true 토글 curl 확인.

## 5. ⚠️ 라이브 AI vs 사전 캐시 (구조 검토)
- 현재 Spring 추천은 **요청 시 passport-ai를 라이브 호출하지 않음**(코드에 라이브 호출 없음, TODO). `cache/{studentId}.json`을 서빙하거나 규칙 폴백.
- 즉 **완전한 AI 5방향 과목 추천**은 사전 생성 캐시가 있는 studentId(예: 데모 `202312345`)에서만 나오고, 새 유저는 진단 기반 규칙 폴백(구분 단위)까지 동작.
- passport-ai는 `from_demo`(데모 JSON)로 오프라인 생성. `from_payload`(Spring 데이터→facts)는 정의만 있고 **브릿지 미구현**.
- 완전 자동화(내 라이브 입력→AI 실시간 추천)를 원하면: Spring이 진단 결과를 passport-ai `from_payload`에 넘겨 `recommend()` 실행 후 cache/{studentId}.json 생성하는 브릿지(FastAPI 또는 subprocess) 신설 필요 → **스트레치**(발표는 캐시+폴백으로 안전).
