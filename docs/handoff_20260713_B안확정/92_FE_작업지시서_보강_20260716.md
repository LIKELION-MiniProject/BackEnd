## 0. 이번 배포로 **계약이 바뀌는 것** 2건 (먼저 읽을 것)

7/16 백엔드 재배포로 응답이 바뀝니다. **89 문서와 mocks/ JSON은 이 2건에 대해 낡았습니다.**

### ① `credit`이 정수 → 소수 (0.5학점 지원)

`인성과미래설계Ⅰ` 같은 0.5학점 과목을 실제 값으로 입력할 수 있게 `credit`이 `double`이 됐습니다.

| 필드 | 이전 | 지금 |
|---|---|---|
| `courses[].credit` | `3` | **`3.0`** |
| `totalCredit.earned` / `shortfall` | `39` / `91` | **`39.5`** / **`90.5`** |
| `categories[].current` (대시보드) | `39` | **`39.5`** |
| `semesters[].earnedCredit` (gpa-trend) | `22` | **`22.0`** |
| `requestedCredits` / `earnedCredits` | `22` | **`22.0`** |

**🔴 FE가 할 일 — 대부분 아무것도 안 해도 됩니다.** `JSON.parse('{"credit":3.0}').credit`은 JS에서 그냥 숫자 `3`이고, `` `${3}` ``은 `"3"`입니다. **그대로 두면 정상 동작합니다.**

단, 아래 두 경우만 확인하세요:

```js
// ❌ 이렇게 하면 "3.0학점"으로 보입니다
`${course.credit.toFixed(1)}학점`

// ✅ 정수면 소수점을 떼는 포맷터
const fmtCredit = (c) => (c == null ? '-' : Number.isInteger(c) ? String(c) : String(c));
// 3 → "3",  0.5 → "0.5",  39.5 → "39.5"
```

- `required`는 **여전히 정수**입니다(요건 기준값 130·21·39는 소수가 없음). 소수는 "이수한 학점" 쪽에만 생깁니다.
- 입력 시 서버가 받는 값: **0 이상 30 이하, 0.5 단위만**. `3.333`을 보내면 `400 COMMON-001 "학점은 0 이상 30 이하의 0.5 단위여야 합니다."`
  근거: [CourseService.validateCredit](../../src/main/java/com/passport/course/service/CourseService.java)

### ② `exam`·`coreLiberal`이 `"완료"` → `"미입력"`

판정할 데이터가 없는데 "충족"으로 표시되던 오표시를 제거했습니다.

| key | 이전 | 지금 |
|---|---|---|
| `exam` (졸업시험/논문) | `current:null, required:null, status:"완료"` | `current:null, required:null, **status:"미입력"**` |
| `coreLiberal` (핵심 교양) | `current:0, required:5, status:"진행중"` | **`current:null, required:null, status:"미입력"`** |

**🔴 FE가 할 일** : `status === "미입력"` 이거나 `required == null` 이면 **막대·퍼센트를 그리지 마세요.** 상태 텍스트만 표시합니다.

```js
const drawBar = (c) => c.required != null && c.status !== '미입력';
```

- `exam`이 "완료"였던 건 계산이 아니라 버그였습니다. 빅데이터AI 전공은 `thesisCertRequired=false`라 "졸업시험 요건 없음"으로 resolve됐고, 그게 "완료"로 잘못 매핑돼 있었습니다.
- `coreLiberal`의 `0/5`는 "5영역 중 0개 이수"가 아니라 "대상 영역 수"였습니다. 과목↔영역 매핑 데이터가 없어 이수 영역을 계산할 수 없어서 판정 불가를 그대로 알립니다.
- `requiredCourse`는 **그대로**입니다(`required:null`, `unit:"건"`) — 이미 막대를 안 그리고 계셨을 겁니다.

> ⚠️ **`mocks/GET_*.json` 7개는 위 2건 반영 전 응답입니다.** EC2 재배포(STEP 5-1) 후 재생성해서 다시 드립니다. 그 전까지는 이 문서의 표를 기준으로 하세요.

## 1. GPA 그래프 — 학년 표기를 버리고 `연도-학기`로 바꿔주세요

**증상** : 다닌 적 없는 **`3-1`** 이 표시됨 (현재 화면: `1-1` → `3-1` → `3-2(예측)`).

### 먼저 — 데이터 연동은 정상입니다

GPA 값(`3.88` / `3.77` / `3.67`)은 서버 값(`3.875` / `3.7727` / `3.6705`)과 정확히 일치하고, 예측 학기 점선 구분도 잘 되어 있습니다. **틀린 건 라벨 하나뿐입니다.**

### 원인 : 달력 연도로 학년을 계산하고 있음

```
학년 = year - admissionYear + 1

2024 - 2024 + 1 = 1  →  "1-1"   ✅ 우연히 맞음
2026 - 2024 + 1 = 3  →  "3-1"   ❌ 실제는 2학년
```

원석님은 **2024-1 이수 후 군휴학 → 2026.01 복학**이라 **2026-1이 2학년 1학기**입니다. 서버 프로필도 `"grade": 2` 입니다. 연도 차이로 계산하면 **휴학 2년이 학년에 그대로 더해집니다.**

### 🔴 학년 표기는 서버가 지원할 수 없습니다 — 계산으로 못 맞춥니다

서버가 주는 건 `profile.grade`(**현재** 학년)뿐이고, **과거 각 학기가 몇 학년이었는지는 어디에도 없습니다.** 원석님이 실제 이수한 학기는 `1학년1학기 → 2학년1학기`로, **1학년 2학기를 통째로 건너뛰었습니다.**

| 시도 | 결과 |
|---|---|
| 연도 차이로 계산 | `3-1` ❌ (지금 이 버그) |
| 최신 학기에서 거꾸로 세기 | `2-1`의 한 칸 뒤 = `1-2`인데 안 다님 ❌ |

**어떤 계산식으로도 맞출 수 없습니다.** 학기별 학년을 따로 저장해야 하는 문제라 이번 범위 밖입니다.

→ **`연도-학기` 표기가 유일하게 정확합니다.** 시연에도 이게 유리합니다 — "2025년이 왜 없냐"는 질문에 "군휴학입니다"로 답할 수 있지만, `1-1 → 2-1`로 보이면 틀린 채로 넘어갑니다.

**근거** : [GpaTrendResponse.java:12](../../src/main/java/com/passport/gpa/dto/GpaTrendResponse.java) — `SemesterGpa(int year, int semester, Double gpa, double earnedCredit, boolean predicted)`

### 실제 응답 (`GET /api/v1/profiles/{id}/gpa-trend`)

```json
{
  "success": true,
  "data": {
    "semesters": [
      { "year": 2024, "semester": 1, "gpa": 3.875,  "earnedCredit": 17.0, "predicted": false },
      { "year": 2026, "semester": 1, "gpa": 3.7727, "earnedCredit": 22.0, "predicted": false },
      { "year": 2026, "semester": 2, "gpa": 3.6705, "earnedCredit": 0.0,  "predicted": true  }
    ],
    "cumulativeGpa": 3.8158,
    "categoryGpa": [
      { "key": "major",   "label": "전공", "gpa": 3.833 },
      { "key": "basic",   "label": "기초", "gpa": null  },
      { "key": "liberal", "label": "교양", "gpa": 3.8   },
      { "key": "etc",     "label": "기타", "gpa": null  }
    ]
  }

```

### 지침

```js
// ❌ 지금 (학년을 연도 차이로 계산 → 휴학이 학년에 더해짐)
const label = `${s.year - admissionYear + 1}-${s.semester}`;

// ✅ 서버가 준 값을 그대로 씀
const label = `${s.year}-${s.semester}`;        // "2024-1", "2026-1"
// 또는 "2024년 1학기"
```

**바뀌는 결과** : `1-1` / `3-1` / `3-2(예측)` → **`2024-1` / `2026-1` / `2026-2(예측)`**

- **`predicted: true`인 항목은 예측치**입니다(규칙 기반 외삽, AI 아님). 실선이 아니라 **점선·회색** 등으로 구분하고, `earnedCredit: 0.0`이므로 학점 표시는 생략하세요.
- **`gpa: null`** 이면 그 학기에 GPA 대상 과목이 없다는 뜻입니다(P/NP만 수강). 점을 찍지 마세요.
- **`categoryGpa`의 `기초`·`기타`가 `null`인 것은 정상**입니다. 전공기초를 전공필수로 입력하기로 합의했고, 자유선택은 아직 미이수입니다. **`-`로 표시하세요.** `null.toFixed()`는 터집니다.

## 4. 로그인 오류 문구 — BE는 정상, FE 텍스트 문제

**근거** : [AuthService.java:47,50](../../src/main/java/com/passport/auth/service/AuthService.java)

로그인 실패 시 서버는 **이메일이 없든 비밀번호가 틀리든 똑같이** 내려줍니다:

```json
HTTP 401
{ "code": "AUTH-002", "message": "이메일 또는 비밀번호가 올바르지 않습니다." }
```

**이건 의도된 동작입니다.** 둘을 구분해서 알려주면 "이 이메일은 가입돼 있다"는 정보가 새어나갑니다(계정 열거 공격).

→ 로그인 화면에 뜨는 **"이미 등록된 이메일"은 서버가 보낸 문구가 아닙니다.** FE에 하드코딩된 텍스트입니다. **FE/디자인에서 제거**해주세요.

| 상황 | 서버 응답 | 화면 문구 |
|---|---|---|
| 로그인 실패 (이메일 없음/비번 틀림) | `401 AUTH-002` | 서버 `message` 그대로 |
| **회원가입** 시 이메일 중복 | `409 AUTH-001 "이미 사용 중인 이메일입니다."` | 서버 `message` 그대로 |

회원가입에서만 중복을 알려주는 게 맞습니다.

## 6. 오독하기 쉬운 응답 3건

### ⓪ 졸업 인증이 **두 종류**입니다 (이름이 겹쳐 헷갈림)

| 구분 | 엔드포인트 | 값 |
|---|---|---|
| **졸업 인증 체크** | `GET`/`PUT` `/profiles/{id}/certifications` | `LANGUAGE`·`VOLUNTEER`·`THESIS` × **`PASS`·`FAIL`·`NOT_SUBMITTED`** |
| **요건 입력 5분야** | `PUT /profiles/{id}/requirements` 의 `certification` | `foreignLangCert`·`infoProcessing`·`cpr`·`socialService`·`foreignLangExtra` × **`TARGET`·`NOT_TARGET`·`DONE`** |

**"요건 현황에 졸업 인증제 데이터가 없다"** — API는 처음부터 있었고, **아무도 입력을 안 해서 값이 비어 있던 것**입니다. 원석님이 실제 상태를 입력해서 이제 값이 옵니다.

```
GET /profiles/1/certifications
→ [{ "type":"LANGUAGE",  "status":"..." },
    { "type":"VOLUNTEER", "status":"..." },
    { "type":"THESIS",    "status":"..." }]
```

### ① `certifications[].fulfilled` — 체크 표시로 쓰면 안 됩니다

```json
{ "type": "THESIS", "required": false, "fulfilled": true, "status": "NOT_SUBMITTED" }
```

`fulfilled: true`인데 `status: "NOT_SUBMITTED"`입니다. 모순처럼 보이지만 정상입니다.

**`fulfilled`은 "이수했다"가 아니라 "졸업을 막지 않는다"는 뜻입니다.** 필수가 아닌 인증은 제출 안 해도 졸업에 지장이 없으므로 `true`입니다. (이 값은 `eligibleForGraduation` 계산에 쓰입니다.)

| 표시할 것 | 쓸 필드 |
|---|---|
| 체크/미체크 아이콘 | **`status`** (`PASS` / `FAIL` / `NOT_SUBMITTED`) |
| 이 인증이 나에게 필수인가 | `required` |
| ❌ 절대 체크 표시로 쓰지 말 것 | ~~`fulfilled`~~ |

`required: false`인 항목에 초록 체크를 그리면 **"졸업논문 완료"로 오해**됩니다.

### ② `category`에 `MAJOR_BASIC`(전공기초)이 **있습니다**

**89 문서 에러표의 "전공기초 없음"은 틀렸습니다.** 정정합니다.

**근거** : [Course.java:73-79](../../src/main/java/com/passport/course/domain/Course.java)

```
MAJOR_BASIC  MAJOR_REQUIRED  MAJOR_ELECTIVE  GE_REQUIRED  GE_ELECTIVE  GENERAL_ELECTIVE
```

**🔴 그렇지만 `MAJOR_BASIC`을 보내지 마세요.** 팀 합의는 **전공기초 = `MAJOR_REQUIRED`로 입력**이고, 서버의 현재 데이터가 전부 그 합의대로 들어가 있습니다.

`MAJOR_BASIC`을 보내면 **400이 안 나고 조용히 저장**된 뒤, 요건이 `majorBasic: 0`이라 **진단이 어긋납니다.** (`categoryGpa`의 `기초`가 `null`인 것도 이 합의의 결과입니다.)

### ③ 프로필에 "군제대복학"이 **없습니다**

**근거** : [Profile.java:103](../../src/main/java/com/passport/profile/domain/Profile.java)

`enrollmentStatus`의 허용값은 **3개뿐**입니다:

```
"재학생"  "휴학생"  "졸업 예정"
```

원석님 프로필은 **`"재학생"`** 입니다. 화면에 "군제대복학"이 보인다면 **FE 하드코딩**입니다. 그 값은 학적부 원본에만 있고 서버는 모릅니다.

## 6-2. 🔴 스코프 컷 — **홈·마이페이지는 만들지 마세요** (PM 결정 7/16)

신영님 피그마에 **홈**과 **마이페이지** 화면이 있지만, **이번 제출 범위에서 뺍니다.**

| 화면 | 결정 | 이유 |
|---|---|---|
| **홈** | ❌ **컷** | 남은 시간에 신설 불가. 시연은 로그인→성적→진단→AI분석 경로로 충분 |
| **마이페이지** | ❌ **컷** | 위와 동일 |
| 홈 "이번 학기 우선 목표" API | ❌ **만들지 않음** | 숫자(전공 9학점·GPA 3.8 등)의 **산출 규칙이 없다.** 지어내면 "판정은 규칙 기반"이라는 이 서비스의 원칙을 스스로 깨는 것 |

**→ 인서님은 §8 우선순위대로만 하시면 됩니다.** 홈·마이페이지에 시간 쓰지 마세요.

> 발표에서는 "홈 대시보드와 마이페이지는 디자인이 나왔고 백엔드 데이터도 준비돼 있지만, 이번 제출에는 핵심 경로 완성을 우선해 넣지 않았습니다"라고 말하면 됩니다. **BE에는 두 화면에 필요한 필드가 이미 다 있습니다**(학년·이수학기·재학여부·졸업예정·복수전공·지도교수 등) — 없는 건 화면뿐입니다.

### 마이페이지를 만든다면 — 데이터는 이미 다 있습니다

컷 결정과 별개로, **혹시 만드시게 되면 BE 작업이 전혀 필요 없습니다.** `GET /profiles/{id}` 하나면 끝입니다.

```json
{
  "deptCode": "BIGDATA_AI",          // ← 주전공 (한글은 FE 매핑, §6-3-② 참조)
  "studentId": "2024132075",
  "name": "송원석",
  "grade": 2,
  "currentSemester": 1,
  "enrollmentStatus": "재학생",
  "expectedGraduationYear": 2029,
  "doubleMajorType": "해당 없음",
  "additionalMajor": null,
  "advisorProfessor": "강민수"
}
```

**🔴 "주전공은 회원가입에 없다"는 오해입니다.** 회원가입(`POST /auth/signup`)은 `email`·`password`·`nickname` 3개뿐이 맞지만, **주전공은 다음 단계인 프로필 등록에 있습니다.**

```
회원가입   POST /auth/signup   → email, password, nickname
    ↓
프로필등록  POST /profiles      → deptCode(=주전공), studentId, admissionYear, name   ← 여기!
    ↓
GET /auth/me 의 profileId 유무로 온보딩/대시보드 분기
```

**❌ 나이·생년월일은 없습니다.** `User`·`Profile` 어디에도 필드가 없습니다. 피그마의 "21세"는 **화면에서 생략**해주세요. 없는 값을 지어낼 수 없습니다.

**⚠️ `PATCH /profiles/{id}`(수정 기능)를 붙이신다면 반드시 11개 필드 전부 전송하세요.** 일부만 보내면 나머지가 `null`로 덮어써집니다.

## 6-3. 여유 있으면 고칠 것 3건 (각각 한 줄)

### ① `dashboard.gpa` → **`dashboard.semesterGpa`**

최신 학기 GPA 필드명이 `semesterGpa`입니다. 최상위 `gpa`는 **다른 것**(`GpaProgress` 객체 — 요건 대비 GPA 충족 여부)이라 이름이 겹쳐 분리했습니다.

```js
dash.data.semesterGpa   // 3.7727  (최신 학기 GPA)
dash.data.gpa           // { current: 3.8158, required: 2.0, fulfilled: true }  ← 객체!
```

### ② `deptCode` → 한글 학과명 매핑

서버는 코드값만 줍니다. 화면 표기는 FE에서 매핑하세요.

```js
const DEPT_LABEL = { BIGDATA_AI: "빅데이터 인공지능 전공" };
DEPT_LABEL[profile.deptCode] ?? profile.deptCode
```

### ③ 수강 입력 학점 드롭다운에 **0.5 추가**

`credit`이 `double`이 됐는데(§0-①) 드롭다운이 정수 1~6만이면 **`인성과미래설계Ⅰ`(0.5학점)을 입력할 수 없습니다.**

```js
const CREDIT_OPTIONS = [0, 0.5, 1, 1.5, 2, 2.5, 3, 4, 5, 6];   // 0.5 단위
```

> 서버는 **0 이상 30 이하 0.5 단위**만 받습니다. 그 외는 `400 COMMON-001`.
