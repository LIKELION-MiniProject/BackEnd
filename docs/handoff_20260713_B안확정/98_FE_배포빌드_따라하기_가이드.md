# 98 — FE 배포 빌드 따라하기 가이드 (인서님용)

> **누구를 위한 문서** : 프런트엔드(인서)님이 **손으로 하나하나 따라 하면** 외부 배포용 FE 빌드가 완성되도록 만든 문서.
> **끝나면 나오는 것** : `dist` 폴더 (이걸 원석/클로드에게 전달 → 서버에 올려 `http://15.164.84.176/` 에 반영)
> **예상 소요** : 10~15분
> **한 번만 이해하고 갈 것** : 지금 백엔드는 `http://15.164.84.176/` 에 이미 떠 있고, nginx가 **`/api` 로 시작하는 요청만 백엔드로 넘기게** 해놨습니다. 그래서 FE는 API 주소를 `http://...:8080` 같은 **절대주소가 아니라 `/api/v1` 상대주소**로만 바꿔주면 됩니다. 그게 이 작업의 전부입니다.

## 0. 시작 전 준비물 체크

| 확인 | 내용 |
|---|---|
| ☐ | FE 프로젝트 폴더 위치를 안다 (예: `C:\...\passport-frontend`) |
| ☐ | Node.js가 설치돼 있다 (평소 `npm run dev` 되면 OK) |
| ☐ | 코드 편집기(VS Code 등)가 있다 |

> Node.js 설치 여부가 헷갈리면 4단계에서 `node -v` 로 확인합니다. 안 깔려 있으면 https://nodejs.org 에서 LTS 버전 설치 후 진행.

## 1. 프로그램 열기 — VS Code로 FE 프로젝트 열기

1. **VS Code**를 켠다.
2. 상단 메뉴 **File(파일) → Open Folder…(폴더 열기)** 클릭.
3. **FE 프로젝트 폴더**를 선택한다. (예: `passport-frontend`)
   - ✅ 제대로 열렸으면 왼쪽 탐색기에 `package.json`, `src`, `index.html`, `vite.config.js`(또는 `.ts`) 같은 파일이 보인다.
   - ❌ `package.json`이 안 보이면 상위/하위 폴더를 잘못 연 것 → 다시 열기.

1. VS Code 상단 메뉴 **Terminal(터미널) → New Terminal(새 터미널)** 클릭.
   - 단축키: `Ctrl` + `` ` `` (백틱, 숫자 1 왼쪽 키)

## 3. 🔑 (가장 중요) 지금 API 주소를 어디서·어떤 이름으로 쓰는지 찾기

FE 코드가 백엔드 주소를 **어떻게 부르고 있는지**를 먼저 알아야, 그걸 `/api/v1` 로 바꿀 수 있습니다. 두 가지 경우 중 하나입니다.

### 3-1. 코드에서 현재 주소를 검색

1. VS Code에서 `Ctrl` + `Shift` + `F` (전체 검색) 를 누른다.
2. 검색창에 아래를 하나씩 넣어 본다:
   - `localhost:8080`
   - `15.164.84.176`
   - `baseURL`
   - `VITE_`
3. 검색 결과에서 **API 기본 주소를 정하는 곳**을 찾는다. 보통 `axios.create({ baseURL: ... })` 나 `const BASE_URL = ...` 같은 형태.

### 3-2. 찾은 형태에 따라 갈림길

**[경우 A] 환경변수로 쓰고 있다** — 예: `baseURL: import.meta.env.VITE_API_BASE_URL`
→ 변수 이름을 기억한다 (예: `VITE_API_BASE_URL`). **4단계로.**

> ⚠️ 변수 이름이 `VITE_API_BASE_URL`이 아니라 `VITE_API_URL` 등 다를 수 있다. **코드에 실제로 쓰인 이름**을 그대로 써야 한다. Vite는 반드시 `VITE_` 로 시작하는 이름만 화면 코드에서 읽힌다.

**[경우 B] 주소가 코드에 직접 박혀 있다** — 예: `baseURL: "http://localhost:8080/api/v1"`
→ 그 문자열을 **`"/api/v1"`** 로 직접 바꾸고 저장(`Ctrl+S`)한다. 이 경우 4단계(.env 만들기)는 **건너뛰고 5단계로**.

```
// 바꾸기 전
const api = axios.create({ baseURL: "http://localhost:8080/api/v1" });
// 바꾼 후
const api = axios.create({ baseURL: "/api/v1" });
```

> 💡 로컬에서 `npm run dev` 로 개발도 계속 하려면, 직접 박는 대신 [경우 A]처럼 환경변수로 빼는 게 낫습니다. 잘 모르겠으면 지금은 [경우 B]로 간단히 바꿔도 배포엔 문제없습니다.

## 4. `.env.production` 파일 만들기 (경우 A일 때만)

> 경우 B(주소 직접 수정)로 했다면 이 단계는 **건너뛰고 5단계로**.

1. VS Code 왼쪽 탐색기에서 **프로젝트 최상위 폴더**(= `package.json` 이 있는 그 위치)를 클릭.
2. 그 폴더에 **새 파일**을 만든다: 탐색기 빈 곳 우클릭 → **New File(새 파일)** → 파일명 정확히:
   ```
   .env.production
   ```
   (맨 앞의 점 `.` 포함, 오타 주의)
3. 파일이 열리면 **딱 한 줄** 입력한다. 변수 이름은 **3단계에서 찾은 실제 이름**으로:
   ```
   VITE_API_BASE_URL=/api/v1
   ```
   - `=` 양옆에 공백 없이, 값은 따옴표 없이 `/api/v1`.
   - 만약 코드의 변수 이름이 달랐다면 그 이름으로. 예: `VITE_API_URL=/api/v1`
4. **저장**: `Ctrl` + `S`.

> `.env.production` 은 `npm run build`(배포 빌드) 할 때만 자동으로 쓰이는 파일이라, 평소 `npm run dev`(로컬 개발)엔 영향을 주지 않습니다.

## 5. 빌드 실행

터미널(2단계에서 연 창)에 아래를 **순서대로** 입력합니다. 한 줄 치고 `Enter`, 끝날 때까지 기다렸다가 다음 줄.

### 5-1. (선택) Node 설치 확인
```
node -v
```
- ✅ `v18.x` 또는 `v20.x` 같은 버전이 나오면 정상.
- ❌ "인식할 수 없는 명령"이면 Node.js 미설치 → https://nodejs.org LTS 설치 후 VS Code 재시작.

### 5-2. 의존성 설치
```
npm install
```
- 처음 받는 프로젝트가 아니라 이미 `node_modules` 가 있으면 금방 끝나거나 생략해도 됩니다. 확실히 하려면 실행.

### 5-3. 빌드
```
npm run build
```
- 30초~2분 정도 걸립니다.
- ✅ 마지막에 초록색으로 `✓ built in ...` 비슷한 메시지 + `dist/` 관련 파일 목록이 뜨면 **성공**.
- ❌ 빨간 `error` 가 뜨면 → **그 메시지 전체를 복사해서 원석/클로드에게** 보내주세요. (대부분 위 3~4단계 변수 이름 오타)

## 6. 결과 확인 — `dist` 폴더 생겼는지

1. VS Code 왼쪽 탐색기에 **`dist`** 폴더가 새로 생겼는지 본다.
2. 그 안에 **`index.html`** 과 **`assets`** 폴더(js·css 들어있음)가 있으면 정상.

> 이 `dist` 폴더가 이번 작업의 **최종 결과물**입니다.

## 7. `dist` 전달하기

### 7-1. 압축
- **Windows**: 탐색기(파일 탐색기)에서 `dist` 폴더 우클릭 → **압축(ZIP) → "ZIP 파일로 압축"** → `dist.zip` 생성.
- **Mac**: `dist` 폴더 우클릭 → **"dist" 압축** → `dist.zip` 생성.

### 7-2. 보내기
- Slack 스레드에 `dist.zip` 을 **끌어다 올리기**(드래그&드롭) 하고 원석/클로드에게 알림.

> 그 뒤는 서버에 올려서 `http://15.164.84.176/` 에 반영하는 작업 — **원석/클로드가 처리**합니다. 인서님 작업은 `dist.zip` 전달까지입니다.
