## 4. AI 경로 (통과 — 설계가 특히 견고)

**유저 자유 텍스트가 Gemini에 도달하지 않는다.** 이번 정독에서 확인한 가장 중요한 안전 특성:

1. **입력 격리**: 유저가 입력한 과목명은 `bridge.py`에서 카탈로그 정확 일치로 **courseCode로 치환**되고, 불일치는 **탈락**한다. 프롬프트(`prompt.py`)에 들어가는 것은 카탈로그 데이터·숫자(부족학점·GPA)뿐 → **프롬프트 인젝션 표면 사실상 0**.
2. **출력 격리(환각 차단)**: AI가 고른 courseCode가 해당 방향 후보 밖이면 **폐기**(`validate.py`), pydantic 스키마(`gemini.py`)로 구조 강제. AI는 "후보 중 선택 + 이유 문장 2개"만 담당.
3. **3중 폴백**: AI 실패 → 기존 캐시 → 규칙 폴백(부족 구분 안내, 과목을 지어내지 않음). `MIN_AI_VALID=3` 미만이면 live로 위장하지 않고 `fallback` 표시.
4. **프로세스 격리**: 별도 Python 프로세스 + 60초 타임아웃 + `destroyForcibly` + 논블로킹 파이프(96 리포트 상세).
5. **경로 조작 방지**: 캐시 파일명은 `sanitize()`(영숫자·-·_만)로 정제 — studentId로 디렉터리 탈출 불가.

## 6. 🔍 발견 사항 (심각도순)

### F1. 🟡 Course 계열 DTO에 입력 검증 부재 → 잘못된 값이 400 대신 500

- **실측**: `grade:"Z"` 전송 → **500 COMMON-004** (라이브 확인). `name:null`도 DB 제약(`nullable=false`) 위반으로 500 예상.
- **원인**: `@Valid`가 auth DTO에만 있음. enum 파싱 실패(`HttpMessageNotReadableException`) 전용 핸들러도 없어 최후 핸들러(500)로 떨어짐.
- **영향**: **낮음** — FE가 드롭다운으로 값을 제한하므로 정상 사용자 경로에서 발생 안 함. 보안 문제 아님(예외는 안전 처리되고 서버는 계속 동작).
- **조치**: 코드 동결 중이므로 **제출 후 백로그** — ① `HttpMessageNotReadableException` 핸들러 추가(400) ② Course/Profile DTO에 `@NotBlank`/`@NotNull` + `@Valid`.

### F2. 🟡 미인증 401 응답의 본문이 비어 있음

- **실측**: 무토큰/위조토큰 401의 본문이 빈 문자열. (로그인 실패 401은 `AUTH-002` JSON 정상.)
- **코드상으론** `JwtAuthenticationEntryPoint`가 JSON을 쓰게 돼 있으나 실제 응답엔 미포함 — 배선 또는 커밋 시점 문제로 추정.
- **영향**: **낮음** — FE는 상태코드(401)로 로그인 화면 분기하면 되고, 상태코드는 정확함.
- **조치**: 제출 후 백로그. FE엔 "401은 본문 없이 올 수 있음"만 공유(92 문서 에러표 정정과 합치).

### F3. 🔵 재수강(retake) 플래그가 GPA 계산에 미반영 (관찰)

- `Course.retake` 필드는 저장되지만 `GpaCalculator`는 무시 — 재수강 시 **원과목과 재수강 둘 다** GPA·학점에 집계된다.
- 실제 학사 규칙(보통 최고 성적만 인정)과 다를 수 있으나, **시연 데이터에 재수강 케이스가 없어**(원석 GPA가 성적표와 일치 실증) 발표 영향 없음.
- **조치**: 명세에 재수강 규칙 자체가 없음 — 제출 후 정책 결정 필요 항목으로 기록.

### F4. 🔵 h2-console 접근 시 404 대신 500 (기지, 미관상)

- 콘솔은 확실히 미노출(목적 달성). 84 §6-3에 기록된 알려진 현상. `application-prod.yml` 분리로 제출 후 정리(94 백로그에 이미 있음).

### 참고 (문제 아님, 알려진 계약·상태)

- `PATCH /profiles`·`PUT /courses`·`PUT /requirements`는 **전체 필드 전송** 필요(부분 전송 시 null/0 덮어쓰기) — 94 §4-⑥에 문서화된 계약, FE 준수 사항.
- `MAJOR_BASIC`은 enum에 실재하나 FE는 보내면 안 됨(요건과 어긋남) — 93 §7 확정.
- CORS 허용이 localhost:5173/5174뿐 — **공개 사이트는 same-origin이라 CORS 자체가 불필요**(정상), FE 로컬 개발도 허용 목록에 있어 문제 없음.
- nginx 정적 루트는 현재 **임시 안내 페이지** — 인서님 dist 배치 대기(97 문서 B-2').
- demo1/demo2는 profileId=null — 온보딩 후 사용 가능(의도된 시드), 폴백 배지 시연 제약은 미결정 #1 그대로.

## 8. 결론·권고

**발표·제출을 막는 문제는 없다.** 보안 축(인증·소유검증·시크릿)은 코드와 실측 양쪽에서 견고하고, AI 경로는 입력·출력 양방향 격리로 설계 수준이 높다. 서버는 이중 안전망(자동복구+스왑)까지 갖춰 안정 상태다.

- **제출 전 (코드 수정 없음 유지)** : F1·F2는 건드리지 않는다 — 정상 사용자 경로에서 발생하지 않고, 지금 코드를 여는 것이 더 위험(94 §7 동결 원칙). 남은 실행 항목은 검토 밖의 기존 잔여(FE dist 배치, mocks 재생성, 리허설 3회)뿐.
- **제출 후 백로그 (94 §6에 추가)** : ① F1 — `HttpMessageNotReadableException` 400 핸들러 + Course/Profile DTO `@Valid` ② F2 — 401 본문 배선 확인 ③ F3 — 재수강 GPA 정책 결정 ④ F4 — `application-prod.yml` 분리(기존 항목).

> **검토 이력** : 라이브 프로브 중 서버 데이터 변경 0건 (쓰기 시도는 전부 403으로 차단됨을 확인하는 테스트였고, 실제로 차단됨). 검토 중 발생시킨 ERROR 로그 1건(#10 프로브)은 무해.
