# 발표 스크립트 (1분) — 왜 H2를 썼나 · 비전공자용

> **용도** : 심사·청중에 비전공자가 있어도 이해되도록, 어려운 용어는 비유로 푼 1분 발표용.
> **톤** : 그대로 읽어도 자연스럽게. 굵은 부분만 힘줘 말하면 됨.

---

## 🎤 1분 스크립트 (그대로 읽기)

"저희는 데이터를 저장하는 **데이터베이스**로, 흔히 쓰는 MySQL 대신 **H2**를 선택했습니다.

쉽게 비유하면, 데이터베이스는 **데이터를 넣어두는 창고**예요. MySQL은 **창고 건물을 따로 짓는** 방식이고, H2는 **앱 안에 서랍장을 넣는** 방식입니다.

저희 서버는 무료로 제공되는 **작은 사양(메모리 2기가) 한 대**인데, 여기에 앱과 AI 기능이 함께 돌아갑니다. 특히 **AI 추천이 실행될 때마다 메모리를 꽤 차지**해서, 여러 명이 동시에 쓰면 부담이 커집니다.

여기에 MySQL이라는 '**별도 창고**'까지 두면 서버가 미리 잡아두는 메모리가 **약 3배로** 늘어, 그만큼 동시 사용 여유가 줄어듭니다. 그래서 **앱에 내장되는 H2로 자원을 아꼈고**, 데이터는 파일로 저장해 **서버를 껐다 켜도 유지**되도록 했습니다.

H2도 **정식 데이터베이스**라, 실제로 **MySQL로 바꾸는 것도 테스트**해봤고 **설정만 바꾸면 되는 걸 확인**했습니다.

정리하면, 지금은 **제한된 환경에 맞춘 최선의 선택**이고, 필요하면 **언제든 MySQL로 확장**할 수 있습니다."

---

## ✅ 이 스크립트에 담긴 핵심 포인트

1. **일부러** H2를 골랐다 (몰라서가 아니라) — 무료·소형 서버 한 대라는 제약에 맞춘 판단
2. **비유**로 이해: MySQL=별도 창고 / H2=앱 안 서랍장
3. **진짜 병목은 AI 기능의 메모리** — DB가 아니라
4. MySQL을 얹으면 **예약 메모리 약 3배** (하드 넘버 "400MB" 대신 안전한 표현)
5. H2 파일 모드라 **데이터 영속** (껐다 켜도 유지)
6. H2도 정식 DB → **MySQL 전환 검증 완료**, 확장 가능

## 💬 질문 오면 (한 문장 답)

- **"실서비스엔 MySQL 아닌가요?"** → "맞습니다. 대규모 운영이라면 넉넉한 서버에 MySQL을 씁니다. 이번엔 프로토타입 검증·데모가 목적이라 H2가 최선이었고, 전환은 설정 수준이라 검증까지 해뒀습니다."
- **"H2는 테스트용 아닌가요?"** → "인메모리로 쓰면 그렇지만, 저희는 **파일 모드**로 써서 데이터가 영속됩니다."
- **"데이터 안 날아가요?"** → "파일로 서버 디스크에 저장돼 재시작에도 유지됩니다."

## ⚠️ 말할 때 피할 것

- ❌ "프리티어라 메모리가 부족해서" — 2기가는 오히려 여유 있는 프리티어 선택. → ✅ "작은 서버 한 대에 AI까지 함께 돌려서"
- ❌ "동시 5명이면 죽습니다" (측정 안 한 단정) → ✅ "동시에 쓰면 여유가 줄어듭니다"
