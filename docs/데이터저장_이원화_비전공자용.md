# 데이터를 왜 두 군데에 나눠 저장했나 — 쉽게 설명 (비전공자용)

> 어려운 용어 없이, 비유로 이해하는 문서. 원본(전공자용 상세): `데이터저장_이원화_설계리포트.md`

---

## 한 줄 요약

우리 서비스가 다루는 정보는 **성격이 정반대인 두 종류**라서, **각자에게 맞는 방식으로** 따로 저장했어요.

- **계속 바뀌는 정보** → **DB**(데이터베이스)에
- **거의 안 바뀌는 정보** → **파일** 하나에

---

## 1. 우리가 다루는 정보는 두 종류예요

| | ① 학생이 하는 것 | ② 학교가 정해둔 것 |
|---|---|---|
| 예시 | 회원가입, 내 프로필, 내가 들은 과목·성적 | 학교 개설 과목 목록(182개)과 각 과목 특징 |
| 얼마나 자주 바뀌나 | **수시로** (입력·수정·삭제) | **거의 안 바뀜** (학기에 한 번 정도) |
| 누구 것 | 사람마다 다름 | 모두 똑같이 공유 |

한마디로 **①은 "살아 움직이는 정보"**, **②는 "붙박이 참고 자료"**예요.

---

## 2. 그래서 저장하는 곳도 두 군데예요

### ① 학생 정보 → **DB** (계속 정리·수정되는 똑똑한 서랍)

비유하면 **자물쇠 달린 정리 서랍**이에요.
- 여러 사람이 동시에 자기 것을 넣고 고치고 지워도 안 엉키게 관리해줘요.
- "이 서랍은 이 사람 것" 하고 주인을 확인해서 남의 걸 못 보게 막아요.
- 이런 기능이 **계속 바뀌는 정보**엔 꼭 필요하죠.

### ② 과목 목록 → **파일** 하나 (한 번 인쇄해두고 다 같이 보는 책자)

비유하면 **학교 요람(과목 안내 책자)**이에요.
- 내용이 거의 안 바뀌니까, 한 번 만들어두고 **그냥 읽기만** 하면 돼요.
- 안 바뀌는 책을 굳이 "자물쇠 서랍(DB)"에 넣어 관리할 이유가 없어요. 넣으면 복잡하기만 하고 좋아지는 게 없어요.

---

## 3. "왜 굳이?" 하는 질문에 미리 답하면

**Q. 그냥 둘 다 DB에 넣으면 편하지 않아요?**
> 안 바뀌는 책자(과목 목록)를 자물쇠 서랍(DB)에 넣는 건 오히려 번거롭기만 해요. 게다가 이 목록을 읽어서 쓰는 건 **AI 추천 기능(파이썬)**인데, 파일로 두면 AI가 DB를 몰라도 돼서 **서로 얽히지 않아요.** 딱 필요한 만큼만 단순하게 만든 거예요.

**Q. 왜 MySQL 같은 걸 안 썼어요?**
> 우리 서버는 무료로 제공되는 **작은 서버 한 대**예요. 여기에 앱과 AI가 함께 돌아가는데, MySQL이라는 무거운 프로그램을 하나 더 띄우면 **메모리 여유가 크게 줄어요**(약 3배 더 차지). 그래서 앱에 **가볍게 내장되는 DB(H2)**를 썼어요. 이것도 똑같은 방식(SQL)으로 동작하는 정식 DB고, **파일로 저장해서 서버를 껐다 켜도 데이터가 남아요.** 실제로 MySQL로 바꾸는 것도 테스트해봤고, **설정만 바꾸면 되는** 걸 확인했어요.

**Q. 나중에 학생이 많아지면요?**
> 그때는 과목 목록도 DB로 옮기는 게 맞아요. 그런데 지금은 한 학과 182개 과목이라 파일이 제일 단순하고 빨라요. 옮겨야 할 때 **고칠 곳이 딱 한 군데**라서 어렵지 않게 바꿀 수 있게 만들어뒀어요.

**Q. 과목 이름으로 맞춘다던데, 이름이 조금 다르면 틀리지 않아요?**
> 이름이 안 맞으면 그 과목은 **AI 추천의 "성향 분석"에서만 빠져요.** **졸업 학점 계산이나 졸업 가능 여부는 절대 안 틀려요** — 그건 AI가 아니라 **정해진 규칙(계산 코드)**이 따로 처리하거든요. 즉 실수해도 중요한 판정은 안전해요.

---

## 4. 제일 중요한 원칙 하나

> **"학점이 몇 점인지, 졸업이 되는지 같은 '사실'은 정해진 규칙이 계산하고, AI는 '무슨 과목이 너한테 좋을지'만 거들어요."**

그래서 AI 쪽에서 작은 실수가 나도, **졸업 판정 같은 중요한 결과는 흔들리지 않아요.** 데이터를 나눠 저장한 것도 이 원칙의 연장선이에요.

---

## 5. 한 장 정리

```
살아 움직이는 정보(회원·성적)   → DB(자물쇠 서랍)      : 계속 바뀌니까
붙박이 참고 자료(과목 목록)      → 파일(요람 책자)      : 거의 안 바뀌니까
무거운 MySQL 대신 가벼운 H2      → 작은 서버 한 대라서   : 자원 아끼려고
이름 매칭이 틀려도               → 졸업 판정은 안전       : 규칙이 따로 계산하니까
```
