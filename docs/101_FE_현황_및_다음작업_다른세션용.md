## 2. 지금까지 진행된 것 (현황)

### ✅ 되어 있는 것
- **로그인/인증** 동작 (JWT `localStorage.accessToken`).
- **읽기(GET) 연동** — 성적·진단·대시보드·AI 분석 화면이 서버 실데이터를 표시함. (예: 성적 화면에 총 39/130학점·30%·2026-1학기 9과목 22학점·GPA 3.77 등 실값 표시 확인)
- **persona(학습 성향)** 표시.

### ⚠️ 2026-07-17에 진단된 이슈 (라이브 검증됨)
1. **"어제는 됐는데 오늘 안 됨" + 콘솔 CORS 에러** → **원인은 만료된 토큰**이다.
   - JWT 수명 = **1시간**. FE가 어제 토큰(만료)을 재사용 → 모든 인증 요청 401.
   - 서버는 401 응답에 CORS 헤더를 안 실어서, **브라우저가 401을 "CORS 에러"로 잘못 표시**한다. → **CORS 문제 아님.** (서버는 `http://localhost:5173`·`5174`를 이미 허용함 — preflight 200 실측)
2. **성적 화면의 "수강내역 수정/추가/삭제 UI가 사라짐"** — 최근 FE 변경으로 편집 컨트롤이 제거·숨김된 회귀. (백엔드 엔드포인트는 정상 살아있음)
3. **시연 계정 데이터 삭제 우려** — 최신 화면상으로는 데이터가 정상(문서상 실값과 일치)으로 보임. 단 저장 로직이 **파괴적(전체 삭제 후 재삽입 / 목업 배열 통째 전송)**이면 실데이터를 지울 수 있으므로 반드시 개별 CRUD로 고칠 것.

### 🔴 미해결 핵심
- **수강(성적) 쓰기 연동**: 추가/수정/삭제가 서버에 개별 CRUD로 안전하게 저장되도록 연결 + 편집 UI 복구.

## 4. 작업별 상세

### 작업 1 — 401 만료 토큰 처리 (공통)
모든 API 응답 처리부(fetch/axios 래퍼 한 곳)에 추가:
```js
if (res.status === 401) {          // AUTH-003 = 토큰 없음/만료
  localStorage.removeItem("accessToken");
  location.href = "/login";        // 죽은 토큰 재사용 금지
  return;
}
```
> 이게 있으면 "CORS 에러처럼 보이던 것"이 사라지고, 재로그인으로 정상화된다. **서버 CORS는 절대 건드리지 말 것.**

### 작업 2 — 수정 UI 복구 + 개별 CRUD (핵심)
1. **먼저 진단**: 성적/수강 컴포넌트를 찾고(`git log --oneline -15`, 해당 파일 diff) **편집 UI가 왜 사라졌는지**(제거? 숨김? 렌더조건?) 확인 후 보고.
2. **복구**: 수정/추가/삭제 버튼을 되살린다.
3. **저장은 개별 과목 단위로만**:
   - 수정 → `PUT /profiles/{id}/courses/{cid}` (그 과목 **하나만**, **전체 필드**)
   - 추가 → `POST /profiles/{id}/courses`
   - 삭제 → `DELETE /profiles/{id}/courses/{cid}` (사용자가 명시적으로 지운 것만)
   - ❌ **전체 목록 삭제 후 재삽입 / 목업 배열을 서버에 통째로 쓰기 금지** (실데이터 삭제 원인)
4. 목록 표시 소스 = **`GET /profiles/{id}/courses` 응답** (목업 아님).

### 작업 3 — 저장 후 재조회
저장(2)이 성공하면 `GET /profiles/{id}/dashboard`와 `GET /profiles/{id}/courses`를 다시 불러 화면 갱신.

### 작업 4 — AI 분석 호출 규약
| 화면 동작 | 호출 |
|---|---|
| AI 분석 화면 **진입** | `GET /recommendations` (캐시, 즉시. **POST 금지**) |
| "AI 분석" **버튼 클릭** | `POST /recommendations` (**로딩 표시 필수**, 수강 변동 시 수 초) |
- 방향별 과목 필드명은 **`recommendations`** (`items` 아님).
- `thin:true` = "과목 적음" 표시, `caution != null`이면 경고 문구, `source:"fallback"`이면 폴백 배지.

### 작업 5 — dist 빌드
`.env.production`에 `VITE_API_BASE_URL=/api/v1` (상대경로) → `npm run build` → `dist/`를 원석에게 전달.

### 작업 6 — 졸업 인증·요건 입력/수정 (상세)

> **저장소가 백엔드에 실재한다** (엔티티 `Certification`·`UserGraduationRequirement` → DB 테이블). 저장한 값은 **진단·대시보드에 자동 반영**된다(유저 저장값 우선, 없으면 학과 하드코딩 폴백). "저장 API가 없다"는 과거 전제는 틀렸다.

**⚠️ "졸업 인증"이 두 종류라 헷갈린다 — 반드시 구분:**

| 구분 | 엔드포인트 | 값 |
|---|---|---|
| **A. 졸업 인증 체크** | `GET`/`PUT` `/profiles/{id}/certifications` | `LANGUAGE`·`VOLUNTEER`·`THESIS` × `PASS`·`FAIL`·`NOT_SUBMITTED` |
| **B. 요건 입력 5분야** | `PUT /profiles/{id}/requirements`의 `certification` | `foreignLangCert`·`infoProcessing`·`cpr`·`socialService`·`foreignLangExtra` × `TARGET`·`NOT_TARGET`·`DONE` |

#### (A) 졸업 인증 체크 — `certifications`
`GET` 응답(진단에도 동일 포함): `{ type, required, status, fulfilled }`
- 🔴 **`fulfilled`을 체크 아이콘으로 쓰지 말 것.** `fulfilled`은 "이수했다"가 아니라 "졸업을 막지 않는다"는 뜻(필수 아닌 인증은 미제출이어도 `true`). **체크/미체크 아이콘은 `status`로** 그려라.
- `required` = 이 인증이 나에게 필수인가.

`PUT /profiles/{id}/certifications` 요청 본문 (3종 일괄):
```json
{ "items": [
  { "type": "LANGUAGE",  "status": "NOT_SUBMITTED" },
  { "type": "VOLUNTEER", "status": "PASS" },
  { "type": "THESIS",    "status": "NOT_SUBMITTED" }
] }
```

#### (B) 졸업 요건 입력 — `requirements`
`PUT /profiles/{id}/requirements` 요청 본문 (요건 입력 화면 5섹션):
```json
{
  "credits": {
    "total": 130, "majorRequired": 21, "majorElective": 39, "majorBasic": 0,
    "liberalRequired": 14, "liberalElective": 21, "majorTotal": 60, "liberalTotal": 35,
    "teaching": 0, "generalElective": 35, "external": 0, "doubleMajor": 0,
    "minor": 0, "linkedMajor": 0, "convergenceMajor": 0
  },
  "requiredCourseType": "...",
  "coreLiberal": [
    { "areaNo": 1, "areaName": "언어와 문학", "courseCount": 1, "credit": 3, "target": true }
  ],
  "certification": {
    "foreignLangCert": "TARGET", "infoProcessing": "NOT_TARGET",
    "cpr": "TARGET", "socialService": "TARGET", "foreignLangExtra": "NOT_TARGET"
  },
  "graduationExam": "NONE",
  "draft": false
}
```
- `credits`는 **15필드 전부 정수, 전체 전송** (일부만 보내면 나머지 `null`로 덮임)
- `graduationExam`: `NONE`·`THESIS`·`EXAM`·`EITHER` — **`THESIS`/`EITHER`로 저장하면** 대시보드 `exam`이 "미입력" 대신 실제 판정 시작
- `coreLiberal[].target` = "이 영역이 나에게 해당하는가"(이수 여부 아님)
- `draft:false`로 저장(임시저장이면 `true`)

**작업 순서**: 화면(신영 디자인 요건 입력 카드) 복구 → `GET`으로 기존값 로드 → 수정 → `PUT` 저장 → 저장 후 `GET /dashboard`·`GET /diagnosis` 재조회로 반영 확인.

## 5. API 계약 (자체완결)

**Base** `/api/v1` · **Content-Type** `application/json; charset=UTF-8`
**인증** `signup`·`login` 외 전부 `Authorization: Bearer <JWT>`
**공통 응답** `{ "success": true, "data": {...}, "message": null }` · **에러** `{ "code": "...", "message": "..." }`

| method | 경로 | 설명 |
|---|---|---|
| POST | `/auth/signup` | `email`·`password`(8자+)·`nickname` |
| POST | `/auth/login` | → `accessToken`·`userId`·`nickname` |
| GET | `/auth/me` | → `userId`·`email`·`nickname`·**`profileId`**(null이면 온보딩) |
| POST | `/profiles` | `deptCode`·`studentId`·`admissionYear`·`name` (주전공=여기, 회원가입 아님) |
| GET | `/profiles/{id}` | 마이페이지 필드 전부 |
| PATCH | `/profiles/{id}` | ⚠️ 11필드 전체 전송 |
| **POST** | **`/profiles/{id}/courses`** | 수강 추가 |
| GET | `/profiles/{id}/courses` | 전 과목 |
| **PUT** | **`/profiles/{id}/courses/{cid}`** | 수정 ⚠️ 전체 필드 |
| **DELETE** | **`/profiles/{id}/courses/{cid}`** | 삭제 |
| GET | `/profiles/{id}/diagnosis` | 졸업 진단 |
| GET | `/profiles/{id}/gpa-trend` | 학기별 GPA |
| GET | `/profiles/{id}/dashboard` | 홈 집계 |
| GET | `/profiles/{id}/recommendations` | 캐시(즉시) |
| POST | `/profiles/{id}/recommendations` | AI 재분석(수 초) |
| GET/PUT | `/profiles/{id}/certifications` | 졸업 인증 3종 |
| GET/PUT | `/profiles/{id}/requirements` | 유저 저장 요건 |

**수강 과목 필드**: `{ name, credit, category, grade, year, semester, retake }`
- `credit`: **0 이상 30 이하 0.5 단위** (표시는 `${c.credit}` 그대로, `.toFixed()` 쓰지 말 것)
- `category`: `MAJOR_REQUIRED` `MAJOR_ELECTIVE` `GE_REQUIRED` `GE_ELECTIVE` `GENERAL_ELECTIVE` — **`MAJOR_BASIC` 보내지 말 것**(조용히 진단 어긋남, 전공기초는 `MAJOR_REQUIRED`로)
- `grade`: `A+` `A` `B+` `B` `C+` `C` `D+` `D` `F` `P` `NP` (화면 `A0` → 서버 `"A"`)
- `PUT`은 **전체 필드** 필수 (일부만 보내면 나머지가 `null`로 덮임)

**주요 에러 코드**

| code | HTTP | 의미 |
|---|---|---|
| `AUTH-003` | 401 | 토큰 없음/만료(1시간) → 재로그인 |
| `AUTH-002` | 401 | 로그인 실패 |
| `AUTH-001` | 409 | 이메일 중복(회원가입) |
| `PROFILE-003` | 403 | 타인 프로필 접근(정상) |
| `COMMON-001` | 400 | 입력값 오류(grade·credit 등) |

## 6. 코드 예시 (수강 CRUD + 401 처리)

```js
const API = import.meta.env.VITE_API_BASE_URL;
const authHeaders = () => ({
  "Content-Type": "application/json",
  Authorization: `Bearer ${localStorage.getItem("accessToken")}`,
});

async function call(path, options = {}) {
  const res = await fetch(`${API}${path}`, { headers: authHeaders(), ...options });
  if (res.status === 401) {                 // 만료 토큰 → 재로그인
    localStorage.removeItem("accessToken");
    location.href = "/login";
    throw new Error("세션 만료");
  }
  const json = await res.json();
  if (!res.ok) throw new Error(json.message || "요청 실패");
  return json.data;
}

const loadCourses  = (pid)        => call(`/profiles/${pid}/courses`);
const addCourse    = (pid, form)  => call(`/profiles/${pid}/courses`,            { method: "POST",   body: JSON.stringify(form) });
const updateCourse = (pid, cid, f)=> call(`/profiles/${pid}/courses/${cid}`,     { method: "PUT",    body: JSON.stringify(f) }); // 전체 필드
const deleteCourse = (pid, cid)   => call(`/profiles/${pid}/courses/${cid}`,     { method: "DELETE" });
const loadDashboard= (pid)        => call(`/profiles/${pid}/dashboard`);         // 저장 후 재조회

// form = { name, credit, category, grade, year, semester, retake:false }
```
