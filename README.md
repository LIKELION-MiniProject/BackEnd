# PassPort - BackEnd

## 프로젝트 소개

PassPort는 을지대학교 빅데이터인공지능전공 학생을 대상으로 졸업 요건 진단과 AI 기반 과목 추천을 제공하는 학사 대시보드입니다. 이 레포지토리는 멋쟁이사자처럼 14기 미니프로젝트 3팀이 개발하는 PassPort 서비스의 백엔드 서버 코드를 관리합니다.

## 팀 구성

팀은 송원석(PM 및 백엔드 개발), 이은종(백엔드 개발), 황인서(프론트엔드 개발), 임신영(디자인)으로 구성되어 있습니다.

## 기술 스택

백엔드는 Spring Boot 3.3.4와 Java 21을 기반으로 하며 빌드 도구로 Gradle을 사용합니다. 개발 환경에서는 H2 데이터베이스를 사용하고, 인증은 JWT와 BCrypt를 조합하여 처리합니다. AI 기반 과목 추천 기능은 Gemini API를 활용하며, 협업 도구로는 Notion, GitHub, Slack을 사용합니다.

## 빠른 시작 (로컬 실행)

먼저 환경 변수를 설정합니다. 서명 키·만료시간·Gemini 키는 코드에 하드코딩하지 않고 환경 변수로만 주입합니다.

```bash
# 1) 백엔드 실행에 필요한 환경 변수 (예시값 — 실제 값으로 대체)
export JWT_SECRET="로컬용-충분히-긴-랜덤-문자열"
export JWT_EXPIRATION=3600000          # 토큰 만료(ms)
# AI 추천을 실제로 호출하려면 passport-ai/.env 에 GEMINI_API_KEY 등을 설정 (없어도 캐시로 동작)

# 2) 백엔드 기동 (H2 파일 DB가 ./data 에 생성됨, 첫 기동 시 데모 계정 시드)
./gradlew bootRun            # Windows: gradlew.bat bootRun  →  http://localhost:8080

# 3) 프런트엔드 (별도 레포/디렉터리)
npm install && npm run dev   # VITE_API_BASE_URL 을 백엔드 주소로 설정
```

**데모 계정** : `demo1@passport.ac.kr` / `demo2@passport.ac.kr` (비밀번호 `Passport1!`). 두 계정은 프로필이 없는 상태로 시드되므로 로그인 후 온보딩(프로필 등록 → 수강 입력)을 거쳐야 진단·추천 화면을 볼 수 있습니다.

> AI 추천은 원칙상 조회(GET)마다 호출하지 않고 **생성 시점(POST)에 1회** 호출해 캐시에 저장합니다. Gemini가 `429/503`이거나 키가 없으면 캐시로 폴백하므로, 키 없이도 데모 흐름은 동작합니다.

## 배포 (운영 환경)

발표·시연은 AWS EC2에 상시 가동된 서버로 진행하며, 외부 사용자 누구나 접속할 수 있도록 nginx 리버스 프록시로 공개합니다.

| 항목 | 값 |
|---|---|
| 서버 | AWS EC2 (Ubuntu 24.04, `ap-northeast-2`), systemd `passport.service` 상시 가동 |
| 공개 접속 주소 | `http://15.164.84.176/` (nginx, 포트 80) — 외부 사용자용 |
| API 직접 주소 | `http://15.164.84.176:8080/api/v1` (백엔드 단독, 디버깅용) |
| 구성요소 | ① nginx(리버스 프록시) ② Spring Boot(JAR, `:8080`) ③ H2 파일 DB ④ `passport-ai`(Python) — 추천/persona 산출 및 캐시 |

**공개 구조** : 브라우저가 `:80`으로 접속하면 nginx가 경로로 나눕니다 — `/api/…`는 Spring(`:8080`)으로 프록시하고, 그 외는 FE 정적파일(`dist`)을 서빙합니다. FE와 API가 **같은 출처**라 CORS·mixed-content가 발생하지 않습니다. nginx는 앞단 프록시일 뿐 백엔드 코드는 건드리지 않습니다. 설정·배포 절차는 [`deploy/nginx/passport.conf`](deploy/nginx/passport.conf)와 `docs/handoff_20260713_B안확정/97_nginx_외부배포_실행가이드.md`를 참조합니다.

`passport-ai`는 Spring이 필요 시 호출하는 파이썬 컴포넌트로, 규칙 기반 후보 선별 위에 Gemini 추천을 얹고 결과를 `passport-ai/cache`에 캐싱합니다. AI는 조회(GET)마다가 아니라 "AI 분석"(POST) 시점에 별도 프로세스로 실행되며, 실패 시 캐시로 폴백합니다(안정성 상세는 `docs/handoff_20260713_B안확정/96_AI_서버_안정성_리포트.md`).

## 핵심 원칙

졸업 가능 여부 판정이나 학점 계산과 같이 사실적으로 확정되는 판정은 모두 규칙 기반 코드로 처리하며, AI는 과목 추천이나 설명을 제공하는 보조적인 용도로만 사용합니다. **한 문장으로: 판정은 규칙, AI는 선택·설명.** MVP 범위는 빅데이터인공지능전공 한 개 전공만 하드코딩하여 지원합니다. Notion에 작성된 API 명세서를 단일 진실 공급원(SSOT)으로 삼아, API를 변경할 때는 반드시 명세서부터 먼저 수정한 뒤 코드에 반영합니다.

## 데이터 고지 (시연·평가용)

시연 데이터 일부는 실측이 아닌 임의값·추정치입니다. 발표 시 "전부 실제 데이터"라고 설명하지 않습니다.

- **성적** : 데모 프로필의 2024-1학기 7과목 성적은 성적조회 기간 밖이라 임의값으로 채워졌습니다. 나머지 학기(2026-1)는 실제 성적표와 일치합니다.
- **강의평가 특성** : 추천 이유 생성에 쓰이는 전공 30과목 강의평가 특성 중 약 17건이 과목 성격 기반 추정치입니다. 실측/추정 구분은 `PassPort_강의평가_입력값_v2.csv` 비고에 표기되어 있습니다.
- **요건 수치** : 빅데이터인공지능전공 졸업 요건(총 130학점 등)은 하드코딩 값이며, 자유선택 35학점 항목은 학과 원본과의 대조 검증이 일부 미완입니다.

## Git 브랜치 전략

main 브랜치는 항상 배포 가능한 상태를 유지하며 직접 push를 금지하고 develop을 통해서만 병합합니다. develop 브랜치는 안정성을 검증하는 단계로 feature 브랜치들을 병합하는 곳입니다. feature 브랜치는 모든 작업이 이루어지는 브랜치로 develop에서 분기하여 작업 완료 후 다시 develop으로 병합합니다.

## 브랜치 이름 규칙

브랜치 이름은 feature/도메인-기능 형태로 작성합니다. 예를 들어 인증 로그인 기능은 feature/auth-login, 수강 이력 CRUD 기능은 feature/course-crud와 같이 작성합니다.

## 작업 시작 표준 순서

작업을 시작할 때는 먼저 develop 브랜치로 이동하여 최신 상태로 pull 받은 뒤, 담당할 기능에 맞는 이름으로 feature 브랜치를 새로 생성합니다. 이후 작업을 진행하며 작은 단위로 자주 커밋하고, 작업이 완료되면 develop 브랜치로 Pull Request를 생성합니다.

## 커밋 컨벤션

커밋 메시지는 type: 요약 형식으로 작성합니다. feat은 새로운 기능 추가, fix는 버그 수정, refactor는 동작 변경 없는 구조 개선, docs는 문서 작업, chore는 설정이나 빌드 등 자잘한 변경을 의미합니다. 커밋은 작은 단위로 자주 나누어 진행합니다.

## 커밋 금지사항

여러 기능을 하나의 커밋에 묶어서 커밋하지 않습니다. 모호하거나 의미를 알 수 없는 커밋 메시지는 사용하지 않습니다. API 키, 비밀번호, JWT 서명키 등 민감한 시크릿 정보는 어떤 경우에도 커밋에 포함하지 않습니다.
